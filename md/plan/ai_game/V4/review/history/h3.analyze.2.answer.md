# h3 问题2 分析：为什么只有预热没有播放

## 语音播放完整链路

```
编排agent(/game/orchestration/minigame)
  → 发言agent(/game/streamlines)
    → 前端 waitForMessageReveal
      → playMessageAudio
        → playMessageAudioWithBinding
          → resolveRuntimeVoiceUrl        ← 预热（/game/streamvoice）✅ 有调用
          → fetchRuntimeVoiceBlob         ← 播放（/voice/audioProxy）❌ 没调用
          → playRuntimeVoiceBlob          ← 实际播放音频
```

## 根因分析：为什么 request 失效

`runtimeVoiceRequestId` 是一个递增计数器，`stopRuntimeVoicePlayback()` 每次调用都会 +1。

`playMessageAudioWithBinding` 开头（ScenePlay.vue:2673）：
```typescript
stopRuntimeVoicePlayback();  // requestId += 1，之前的播放请求全部作废
const requestId = runtimeVoiceRequestId;  // 记住当前 requestId
```

如果 `resolveRuntimeVoiceUrl`（预热）执行期间，另一个调用触发了 `stopRuntimeVoicePlayback()`，那么 `requestId !== runtimeVoiceRequestId` 为 true，播放被静默跳过。

## 当前战斗模式的流程问题

当前战斗模式走的是 **直接 streamlines**，没有经过编排：

```
用户发言 → addMessage(orchestrate:false)
  → 后端 handleMiniGameTurn 返回 narrativePlan
    → 前端检测 hasMiniGamePlan
      → 直接 streamSessionPlan(narrativePlan)
        → /game/streamlines（发言agent）
```

问题在于 `sendMessage` 中（useToonflowStore.ts:6493）：
```typescript
await streamSessionPlan(result.narrativePlan as DebugNarrativePlan, [...state.messages]);
return;  // 不清除面板，不继续常规流程
```

`streamSessionPlan` 完成后，在内部（useToonflowStore.ts:6650）：
```typescript
if (hasActiveMiniGameInCurrentSession()) {
  const chainedMiniGamePlan = getPendingMiniGameNarrativePlan();
  if (chainedMiniGamePlan) {
    await streamSessionPlan(chainedMiniGamePlan, conversationMessages()); // 立即链式调用
    return;
  }
  clearPendingSessionOrchestrationPrefetch();
  return;  // 直接返回，不走 continueSessionNarrative
}
```

**链式调用问题**：当有 chainedMiniGamePlan 时，`streamSessionPlan` 会立即再次被调用。这时：
1. 第一条消息还在 `waitForMessageReveal` 中播放语音
2. 第二条 `streamSessionPlan` 创建新消息 → 触发 reveal watch → `stopRuntimeVoicePlayback()` 中断
3. 第一条消息的 `resolveRuntimeVoiceUrl` 完成后，发现 `requestId !== runtimeVoiceRequestId`，直接 return false
4. 结果：只有预热（streamvoice），没有播放（audioProxy）

## 对比：正常模式（非战斗）的语音播放链路

正常模式走 `performContinueSessionNarrative`（useToonflowStore.ts:6803）：
```
resolveSessionOrchestration → 返回 plan
  → streamSessionPlan → 流式消息 → commit
    → 不链式调用，等 waitForMessageReveal 完成
    → 下一轮 continueSessionNarrative 触发下一条
```

关键区别：正常模式是 **串行** 的，一条消息播完再走下一条。战斗模式是 **链式** 的，`streamSessionPlan` 内部直接链式调用下一条，不等前一条语音播完。

## 解决方案：走 /game/orchestration/minigame

按照 h3.analyze.2.md 指出的方向，改为：

```
编排agent(/game/orchestration/minigame)
  → 返回 plan（包含 role/roleType/presetContent/motive）
    → 前端 streamSessionPlan(plan)
      → /game/streamlines（发言agent）
        → waitForMessageReveal 播放语音
          → 预热 ✅
          → 播放 ✅
```

这样编排接口作为中间层，每次只返回一个 plan，前端处理完一条再走下一条 `continueSessionNarrative`，不会出现链式中断语音的问题。

### 编排接口需要做的事
1. 新增 `POST /game/orchestration/minigame` 路由
2. 调用 `handleMiniGameTurn` 获取下一个 plan
3. 将 miniGame 的 plan 通过编排接口返回，走标准的 `orchestrateSessionTurn` 流程
4. 前端走 `continueSessionNarrative` → `resolveSessionOrchestration` → `streamSessionPlan`，每条消息串行处理
