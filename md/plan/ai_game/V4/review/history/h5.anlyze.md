# h5 回溯问题分析

## 问题描述

- 消息1（用户发送的 `#挖矿`）可以回溯
- 消息2（旁白规则说明）不能回溯，且回溯后消失
- 消息3（玩家输入「薰儿陪练」）正常

## 消息流程

```
用户发送「#挖矿」
  → orchestrateDebug 调用 handleMiniGameTurn
  → handleMiniGameTurn 返回 intercepted: true
  → 规则说明消息直接通过 sendDebugSuccess 返回给前端
  → 没有调用 saveDebugRevisitPoint 保存回溯数据 ❌

用户发送「薰儿陪练」
  → 同上流程，但这次返回 pendingNarrativePlan
  → 旁白台词由 streamlines 生成，调用 saveDebugRevisitPoint ✅
```

## 根本原因

**`orchestration/index.ts` 第648-673行**：

当 `handleMiniGameTurn` 返回 `intercepted: true` 时，消息直接通过 `sendDebugSuccess` 返回：

```typescript
if (miniGameResult?.intercepted) {
  // ... 构建 presetMessages
  return sendDebugSuccess(params.res, {
    // ...
    messages: [...params.inputMessages, ...presetMessages],  // ❌ 没有保存回溯数据
  });
}
```

对比正常编排流程（经过 `streamlines`）：
```typescript
// streamlines.ts 第429-435行
saveDebugRevisitPoint(
  debugRuntimeKey,
  state,
  fullMessages,
  Number(chapter.id || 0) || null,
  debugMessageCount,  // ✅ 保存了回溯数据
);
```

## 解决方案

### 推荐：在 orchestrateDebug 返回前保存回溯数据

**修改文件**: `src/routes/game/orchestration/index.ts`

**修改位置**: 第662-673行的 `return sendDebugSuccess` 之前

**修改内容**:

1. 导入必要的函数：
```typescript
import {
  // ... 现有导入
  saveDebugRevisitPoint,
  cacheAndBuildDebugStateSnapshot,
} from "../debugRuntimeShared";
```

2. 在 `return sendDebugSuccess` 之前添加：
```typescript
// 保存回溯数据，确保小游戏产生的消息可回溯
const fullMessages = [...params.inputMessages, ...presetMessages];
const snapshot = cacheAndBuildDebugStateSnapshot({
  userId: params.userId,
  worldId: params.worldId,
  state: params.state,
});
const debugRuntimeKey = String(snapshot.debugRuntimeKey || "");
saveDebugRevisitPoint(
  debugRuntimeKey,
  params.state,
  fullMessages,
  responseChapterMeta.chapterId,
  fullMessages.length,
);
```

## 影响范围

此修复影响所有小游戏拦截产生的消息：
- 小游戏规则说明（如「挖矿开始了...」）
- 小游戏动作确认（如「薰儿已准备协助...」）
- 其他由 `handleMiniGameTurn` 直接返回的消息

## 测试验证

修复后需验证：
1. 回溯消息1后，消息2重新出现
2. 消息2有回溯按钮
3. 小游戏状态正确恢复
