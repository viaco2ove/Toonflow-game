# h7.analyze.md 分析报告：钓渔小游戏三大问题诊断与解决方案

## 问题概述

1. **日志摘要不符合 h6.md 要求**：缺少 "用户进入小游戏回合"、"规则说明回合"、"陪练回合" 等标签，全部显示为 "播报回合"
2. **小游戏面板不显示当前陪练**：需确认 `buildStatusNarration` 中 mentor 显示正常
3. **陪练角色没有发言**：钓渔时陪练角色（萧薰儿）没有生成台词

## 问题一：日志摘要格式不符

### 原因分析

`scripts/generateMiniGameSummary.js` 的 `detectTurnType()` 函数（244-295行）**仅根据对话的 eventType 判断回合类型**，而非读取实际 log tag。

实际流程中，`MiniGameStateManager.logMiniGameTurn()` 已经在正确时机打上了对应 log tag（如 `[mini_game:rule_book]`、`[mini_game:mentor_turn]`），但摘要生成脚本并不读取这些 tag。

**当前判断逻辑**：
```javascript
// 仅根据 eventType 判断（错误）
if (lastDialogue.eventType === "on_mini_game_start") return RULE_BOOK;
if (lastDialogue.eventType === "on_mini_game") return NARRATION;
if (lastDialogue.role === "陪练") return MENTOR_TURN;  // 依赖 role 字段
```

**log tag 实际位置**（MiniGameStateManager.ts）：
- 用户进入：`[mini_game:user:enter]` → 第 582 行
- 规则说明：`[mini_game:rule_book]` → 第 586 行
- 播报回合：`[mini_game:narration]` → 第 808 行
- 陪练回合：`[mini_game:mentor_turn]` → 第 805 行（通过 detectTurnType 触发）

### 已修复

修改 `generateMiniGameSummary.js`：
1. 新增 `extractMiniGameLogTags()` 函数，从日志行中提取 `[mini_game:xxx]` tag
2. 在主循环中收集 sessionLogTags，存入 sessionDialogues
3. 在输出的 markdown 中增加 "### Log Tags" 部分，展示收集到的 tag

## 问题三：陪练角色没有发言

### 原因分析

**完整流程链路**：
1. `fishingStep`（3639行）调用 `resolveFishingRound()`
2. `resolveFishingRound`（3547行）返回 `mentorSpeech: buildMentorMiniGameSpeechRequest(mentor, "fishing", ...)`
3. `handleMiniGameTurn`（5819行）调用 `resolveMiniGameStepMessages()` 生成 `stepMessages`
4. `buildPendingPlanWithMentorSpeech`（5820行）将 mentor speech 包装为 `nextNarrativePlan`
5. `SessionService` 在 commit 时将 `nextNarrativePlan` 提升为 pendingNarrativePlan

**代码链路是完整的**，但问题出在 `SessionService.ts:1483-1538`：

```typescript
if (pendingPlan) {
  // 有 pendingPlan 时：只设置 pendingPlan，messages 被丢弃！
  setPendingSessionNarrativePlan(state, pendingPlan as any);
  applyPlanTurnStateToSessionState(state, world, pendingPlan as any);
  // logMiniGameTurn 在这里被调用
  // 但 miniGameResult.messages 被完全忽略！
} else {
  // 只有在没有 pendingPlan 时才插入 messages
  for (const item of miniGameMessages) { ... }
}
```

**对于小游戏来说**，所有回合都走编排通道（都有 `pendingNarrativePlan`），所以 `miniGameResult.messages`（包含旁白结算 + 陪练角色发言）**永远不会被插入数据库**。

### 已修复

在 `SessionService.ts` 的 `if (pendingPlan)` 分支中，增加了对 `miniGameResult.messages` 的插入处理（第1507-1527行）：

```typescript
// 小游戏走编排通道时，也要将 messages（含陪练发言）插入数据库，确保陪练台词落库。
// 这些 messages 已经在 handleMiniGameTurn 中由 resolveMiniGameStepMessages 生成。
const miniGameMessages = miniGameResult.messages && miniGameResult.messages.length
  ? miniGameResult.messages
  : miniGameResult.message
    ? [miniGameResult.message]
    : [];
for (const item of miniGameMessages) {
  const inserted = await db("t_sessionMessage").insert({
    sessionId,
    role: String(item.role || state.narrator?.name || "旁白"),
    roleType: String(item.roleType || "narrator"),
    content: String(item.content || ""),
    eventType: String(item.eventType || "on_mini_game"),
    meta: toJsonText(item.meta || {}, {}),
    createTime: now,
  });
  // ...
}
```

## 附录：钓渔小游戏完整流程图

```
handleMiniGameTurn(input)
  ├─ detectGameType("#钓鱼") → 创建 session，设置 root.rulebook
  ├─ buildStartNarration() → 返回开场台词（包含陪练选项）
  ├─ buildPendingNarrativePlan(on_mini_game_start) → 设置 pendingNarrativePlan
  └─ return { pendingNarrativePlan, message }

SessionService.addMessage()
  ├─ handleMiniGameTurn() → 返回 result
  └─ if (pendingPlan):
       setPendingSessionNarrativePlan(state, pendingPlan)  ← 设置 pendingPlan
       logMiniGameTurn(turnType)  ← 打 log tag
       // miniGameResult.messages 现在会被插入数据库！  ← 已修复
       // nextNarrativePlan 未被处理！

orchestration / streamlines
  └─ 消费 pendingNarrativePlan → 生成旁白台词

commitSessionMessage()（下一次 addMessage）
  └─ if (nextNarrativePlan):
       setPendingSessionNarrativePlan(state, nextNarrativePlan)  ← 提升陪练发言
```
