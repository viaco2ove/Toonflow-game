# h3 问题分析

## 问题1：第一次播报回合（旁白）没有语音

### 现象

用户攻击后，旁白第一句播报：
```
(一道带着劲风的步法残影闪过，异天的攻击擦着萧炎的衣摆扫过，只留下一道浅浅的划痕，萧炎闷哼一声，气血翻涌间血量掉到了72点。)
@萧炎："哼，倒是有点本事……
```
这条旁白消息没有触发 `/voice/audioProxy`，没有语音播放。但紧接着萧炎的第二句和旁白的第三句都正常触发了语音。

### 分析

这条旁白消息的内容格式有问题：

1. **内容包含 `@萧炎：` 前缀** — 这不是旁白该说的话，而是编排师输出格式里"谁在说"的标记。正常流程中，`@角色名：台词` 应该被 `extractDirectiveSpeechIdentity`（NarrativeOrchestrator.ts:1113）解析，角色名赋给 `role`，台词赋给 `content`，最终消息的 `role=萧炎`, `roleType=npc`, `content=哼，倒是有点本事……`。但这里 `@萧炎：` 混进了旁白的 `content` 里，说明**角色发言器（streamlines）或 commit 环节没有正确剥离 `@角色名：` 前缀**。

2. **旁白的 `content` 以 `（...）` 结尾又接了 `@萧炎：`** — `sanitizeSpeechText()`（ScenePlay.vue:396）会剥离括号注解，但 `@萧炎："哼，倒是有点本事……` 残留在文本里。这段文本到语音合成时，TTS 会读出"艾萧炎"这种无意义内容，或者因为格式异常直接跳过语音播放。

3. **根本原因推测**：战斗回合的第一条旁白是 `pendingNarrativePlan` 的 `presetContent`，它把旁白和萧炎的台词合并成了一个 content 字段。MiniGameController 的战斗结算播报（line 1851）设置了 `presetContent`，但内容可能把多角色的台词拼在了一起，而 streamlines 在生成时没有正确拆分。

### 修复方向

- **后端**：检查 `presetContent` 的生成逻辑，旁白内容和角色台词不应合并到同一条消息的 content 里
- **后端**：streamlines/commit 阶段，确保 `@角色名：` 前缀始终被 `extractDirectiveSpeechIdentity` 解析并拆分到正确的 role/content 字段
- **前端兜底**：`sanitizeSpeechText()` 增加 `@角色名：` 前缀的剥离逻辑，避免 TTS 读出角色名

## 问题2：`@萧炎：` 出现在台词内容里

### 现象

旁白消息的 content 里出现了 `@萧炎："哼，倒是有点本事……`，这意味着角色名标记没有被正确解析。

### 分析

正常流程：
1. 编排师输出 `@萧炎：台词` → `extractDirectiveSpeechIdentity` 解析出 `speaker=萧炎`, `body=台词`
2. 编排结果 `plan.role=萧炎`, `plan.roleType=npc`
3. streamlines 生成台词时，`content` 只包含 `台词`，不含 `@萧炎：` 前缀

异常流程（本次 bug）：
- 旁白的 `presetContent` 里混入了 `@萧炎：` 标记
- 这条消息被当作旁白（`roleType=narrator`），但内容里包含了属于萧炎的台词
- streamlines 生成时没有拆分，导致 `@萧炎：` 前缀残留在 content 里

### 修复方向

- **后端**：在 `presetContent` 赋值时，如果内容包含 `@角色名：` 标记，需要拆分成多条消息，每条对应正确的 role/roleType
- **后端**：streamlines 的 commit 阶段，对 content 做 `extractDirectiveSpeechIdentity` 后处理，确保 `@角色名：` 不残留
- **前端**：`sanitizeSpeechText()` 增加对 `@角色名：` 前缀的剥离

## 问题3：正确的台词设计

h3.md 给出的正确设计是：

```
- 用户回合：输入内容
- 旁白说：一道带着劲风的步法残影闪过...（纯旁白，无角色台词混入）
  → 语音播放
- 萧炎说：(动作描写) 方才那步法倒是刁钻...（独立消息，roleType=npc）
  → 语音播放
- 旁白说：(动作描写) 方才的反击竟擦着...（独立消息）
  → 无语音说明（但按正确逻辑也应该播放语音）
- 用户回合, 回合制到敌方或者用户血量为零 或 "#退出"
```

核心要求：
1. **每条消息只包含一个角色的台词**，旁白和角色台词不能混在一条消息里
2. **`@角色名：` 不能出现在 content 里**，应该被解析为 role 字段
3. **每条非用户消息都应触发语音播放**，旁白消息也不应例外
