# 挖矿小游戏问题分析

## 问题现象

用户进入挖矿小游戏后，输入"挖"没有响应正常的挖矿结果，而是收到重复的"当前仍在 挖矿 中，请先完成、暂停或退出小游戏。当前合法动作：需要陪练、不需要陪练、纳兰嫣然、萧炎、小医仙、云韵、药老（药尘）、薰儿（萧薰儿|古薰儿）、美杜莎、海波东（冰皇）、勘探、开采、精挖、支护、清障、休息、撤离。" 提示，导致小游戏无法正常推进。

## 根因分析

### 核心问题：`"挖"` 无法匹配到合法动作 `"开采"`

#### 1. 规则匹配失败（`normalizeActionId`）

挖矿动作 `excavate` 的配置如下（`MiniGameController.ts:3852`）：

```typescript
{ action_id: "excavate", label: "开采", aliases: ["挖矿", "挖掘"] }
```

`normalizeActionId()` 函数（`MiniGameController.ts:4840`）的匹配顺序：

| 匹配方式 | 匹配逻辑 | `"挖"` 能匹配？ | 原因 |
|----------|----------|:---:|------|
| **精确匹配** | `text === item.label` | :x: | `"挖" !== "开采"` |
| **别名匹配** | `text === alias` 或 `text.includes(alias)` | :x: | `"挖" !== "挖矿"`，`"挖"` 不包含 `"挖矿"` |
| **模糊匹配 A** | `text.includes(item.label)` | :x: | `"挖".includes("开采")` → false |
| **模糊匹配 B** | `item.label.includes(text)` | :x: | `"开采".includes("挖")` → false |

**关键缺陷**：别名匹配只做了 `text.includes(alias)` 判断，即**用户输入是否包含别名**，而没有做反向匹配（`alias.includes(text)`）。`"挖矿".includes("挖")` 实际上是 `true`，但这条路径没有被检查。

#### 2. AI 意图解析兜底（`resolveMiniGameIntentByAi`）

当规则匹配失败后，系统调用 AI 模型来解析用户意图。`MiniGameIntentService.ts` 会将：
- 当前游戏阶段、公开状态
- 最近旁白叙述
- 合法动作列表（action_id, label, aliases）
- 用户输入 `"挖"`

发给 AI，期望 AI 返回正确的 `action_id`（如 `"excavate"`）。

**但 AI 解析是概率性的**，不一定每次都正确映射。从日志看，连续多次"挖"都触发 `on_mini_game_invalid`，说明 AI 也没有成功将"挖"映射到"开采"。

#### 3. 挖矿操作引导语误导

挖矿启动时的引导语（日志 line 133）：

```
"挖矿开始了。你准备挖什么矿物？是否需要陪练或角色协助？可选陪练：...
直接输入目标矿物或"勘探""开采""精挖""撤离"。"
```

引导语中的合法操作列表只列出了 `"勘探""开采""精挖""撤离"`，这四个词里**没有任何一个包含"挖"字**。用户看到"挖矿"开始，自然会输入"挖"，但引导语并没有告诉用户可以输入"挖"或"挖掘"。

### 次要问题：用户循环无效输入

从日志分析，用户行为序列为：

| 轮次 | 用户输入 | 系统响应 | 事件类型 |
|------|---------|---------|---------|
| 1 | `#挖矿` | 挖矿启动引导 | `on_mini_game_start` |
| 2 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 3 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 4 | `#退出` | 已强制退出挖矿 | `on_mini_game_abort` |
| 5 | `#挖矿` | 挖矿启动引导 | `on_mini_game_start` |
| 6 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 7 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 8 | `开采` | `矿脉剩余 80...` | `on_mini_game` |
| 9 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 10 | `挖` | 当前仍在挖矿中... | `on_mini_game_invalid` |
| 11 | `萧炎` | 萧炎准备协助挖矿 | `on_mini_game` |

用户**3次**输入"挖"才放弃并退出重进，又输入"挖"无效后才尝试"开采"（有效），之后又回到输入"挖"的循环。这种体验非常糟糕。

## 建议修复方案

### 方案 1（推荐）：在别名匹配中增加反向匹配

修改 `normalizeActionId()` 函数（`MiniGameController.ts:4850-4853`），别名匹配增加反向判断：

```typescript
const aliasMatch = options.find((item) => (item.aliases || []).some((alias) => {
    const normalizedAlias = normalizeMiniGameActionText(alias);
    return text === alias || text.includes(alias) || alias.includes(text)
      || normalizedText === normalizedAlias || normalizedText.includes(normalizedAlias)
      || normalizedAlias.includes(normalizedText);
  }));
```

这样 `"挖矿".includes("挖")` 和 `"挖掘".includes("挖")` 都能匹配成功，将"挖"映射到"开采"。

### 方案 2：为 `excavate` 添加短别名

在 `miningOptions()` 函数（`MiniGameController.ts:3852`）中，为 `excavate` 添加 `"挖"` 别名：

```typescript
{ action_id: "excavate", label: "开采", aliases: ["挖矿", "挖掘", "挖"] }
```

### 方案 3：优化挖矿引导语

将引导语中的合法操作描述改为包含"挖/挖掘"：

```
直接输入目标矿物，或输入"挖""勘探""开采""精挖""撤离"。
```

### 方案 4（治本）：同时做方案1+2+3

1. **增加反向别名匹配**（方案1），让其他小游戏也能受益
2. **显式添加"挖"为别名**（方案2），确保规则匹配
3. **优化引导语**（方案3），让用户一眼就知道可以输入"挖"
