# Bug 分析：自动推进没有产出新内容

## 复现场景

- 会话: `gs_1777316450230_e30c8f5fea`，worldId=28，chapterId=23（第4章）
- 用户输入"走在大街上"后，前端 `performContinueSessionNarrative` 循环3次编排后抛出 `Error: 自动推进没有产出新内容`

## 后端日志实锤

## 根因：小游戏退出不干净

### 事件时序

1. **战斗小游戏胜利** → MiniGameController 返回 `pendingNarrativePlan`：
   - `roleType:"narrator"`, `eventType:"on_mini_game_finish"`, `awaitUser:true`, `presetContent:"战斗胜利文案"`
   - 通过 `setPendingSessionNarrativePlan` 写入 state 并持久化到 DB

2. **小游戏 finish 的 pendingNarrativePlan 被写入但未被 streamlines 消费**
   - `addMessage` 返回了这个 plan 给前端
   - 前端应该调 `/game/streamlines` 生成旁白台词 → commit 清除 pendingNarrativePlan
   - **但前端此时可能还没来得及消费这个 plan**

3. **用户输入 `#退出`** → 进入 `on_mini_game_abort` 分支
   - abort 分支返回 `intercepted: true`，**没有设置新的 pendingNarrativePlan**
   - 但也没有清除旧的小游戏 finish 的 pendingNarrativePlan
   - 走 `allowPlayerTurn` 分支（因为没有 pendingNarrativePlan → 等等，此时 state 里还有旧的）

4. **用户输入 `走在大街上`** → 编排时发现 `pendingNarrativePlan` 存在
   - 但这个 pendingNarrativePlan 已经是过期的（小游戏已退出，不需要再播报胜利旁白）
   - 编排返回了这个过期 plan → 前端不认 `roleType:"player"` 的 plan → 不调 streamlines → 死循环

### 关键代码位置

**小游戏 abort 不清理 pendingNarrativePlan**：
- `MiniGameController.ts:5137-5151` — abort 分支 `clearMiniGameSession(root)` 清了小游戏运行态，但没有清 `state.pendingNarrativePlan`
- `SessionService.ts:1442-1448` — `addMessage` 中 `intercepted: true` 且有 `pendingNarrativePlan` 时，会继续保留它

**pendingNarrativePlan 的清理只靠 commit**：
- `SessionService.ts:2805` — `commitSessionNarrativeTurn` 里 `setPendingSessionNarrativePlan(state, null)` 是唯一可靠的清除点
- 小游戏 abort 走 `addMessage`，不走 streamlines/commit，所以 pendingNarrativePlan 不会被清

### 死循环形成

1. 编排发现 `pendingNarrativePlan` 存在 → 直接返回（不调大模型）
2. 返回的 plan 是 `roleType:"player"`, `awaitUser:true` → 前端 `shouldStreamSessionPlanFromPlan` 返回 false → 不调 streamlines
3. 不调 streamlines → 不 commit → `pendingNarrativePlan` 不被清除
4. 下次编排又返回同一个 plan → 循环3次后抛错

## 修复方向（待确认）

**小游戏 abort/退出时清除 pendingNarrativePlan**：
- 在 `addMessage` 的小游戏 `intercepted` 分支中，当小游戏状态已变更为 finished/aborted 时，主动 `setPendingSessionNarrativePlan(state, null)` 清除过期 plan
- 或者在 MiniGameController 的 abort 分支中，返回一个标记让上层知道需要清除 pendingNarrativePlan
