# h1/h2 修复验证

## 问题描述（h1）
用户发送"走在大街上"后，前端 `performContinueSessionNarrative` 循环3次编排后抛出 `Error: 自动推进没有产出新内容`。

## 问题描述（h2）
小游戏退出不干净，导致后续编排被过期的 `pendingNarrativePlan` 挡住。

## 根因分析

### h1 根因：小游戏退出不干净，`pendingNarrativePlan` 未清除

**事件时序**：
1. **战斗小游戏胜利** → MiniGameController 返回 `pendingNarrativePlan`（胜利播报）
2. **小游戏 finish 的 pendingNarrativePlan 未被消费** → `addMessage` 返回 plan 给前端，但前端可能还没来得及消费
3. **用户输入 `#退出`** → 进入 `on_mini_game_abort` 分支，返回 `intercepted: true`，**但没有清除旧的 `pendingNarrativePlan`**
4. **用户输入 `走在大街上`** → 编排时发现 `pendingNarrativePlan` 存在，直接返回（不调大模型），导致死循环

**死循环形成**：
1. 编排发现 `pendingNarrativePlan` 存在 → 直接返回（不调大模型）
2. 返回的 plan 是 `roleType:"player"`, `awaitUser:true` → 前端 `shouldStreamSessionPlanFromPlan` 返回 false → 不调 streamlines
3. 不调 streamlines → 不 commit → `pendingNarrativePlan` 不被清除
4. 下次编排又返回同一个 plan → 循环3次后抛错

### h2 根因：同 h1
用户分析：退出小游戏的时候要干净一点，在剧情模式的编排阶段再次判断一下是否在小游戏模式。

## 修复方案

### 方案：在 `addSessionMessage` 中清除过期的 `pendingNarrativePlan`

**修改文件**：`src/modules/game-runtime/services/SessionService.ts`

在 `miniGameResult?.intercepted` 分支开头，添加清除逻辑：

```typescript
if (miniGameResult?.intercepted) {
  const pendingPlan = miniGameResult.pendingNarrativePlan;
  // 小游戏退出/中止时，必须清除可能残留的 pendingNarrativePlan，
  // 否则后续编排会被过期的 plan 挡住，导致"自动推进没有产出新内容"的死循环。
  // 参见 h1.md 分析。
  const miniGameEventType = String(miniGameResult.message?.eventType || "");
  const isMiniGameEnded = miniGameEventType === "on_mini_game_abort"
    || miniGameEventType === "on_mini_game_finish"
    || !isMiniGameActiveState(state);
  if (isMiniGameEnded) {
    // 小游戏已结束，清除残留的 pendingNarrativePlan
    if (getPendingSessionNarrativePlan(state)) {
      setPendingSessionNarrativePlan(state, null);
    }
  }
  if (pendingPlan) {
    // 有编排计划：只写入 session.pendingNarrativePlan，由后续 orchestration/streamlines 消费。
    setPendingSessionNarrativePlan(state, pendingPlan as any);
    applyPlanTurnStateToSessionState(state, world, pendingPlan as any);
  } else {
    // ... 原有逻辑
  }
}
```

**关键改进**：
1. **优先清除过期的 `pendingNarrativePlan`**：在小游戏结束时，先清除可能残留的旧 plan，再设置新 plan
2. **判断小游戏是否结束**：通过 `eventType` 或 `isMiniGameActiveState(state)` 判断
3. **避免死循环**：确保 `pendingNarrativePlan` 不会残留到下一次编排
