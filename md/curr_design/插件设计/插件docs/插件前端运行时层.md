# 插件前端运行时层

> 最后更新：2026-09-21
> 范围：把已启用插件的 `manifest.contributes` 暴露到前端 UI（命令面板、minigame iframe 容器）

---

## 1. 设计目标

实现「B+C」组合：

| 模块 | 能力 | 关键文件 |
|------|------|---------|
| **B. 运行时注入层** | 把插件 `contributes.sidebar` 自动注入到 `#` 命令面板；插件安装/卸载/启停后自动刷新 | `src/composables/usePluginRuntime.ts` |
| **C. minigame 容器** | 当 `activeMiniGame.gameType` 命中插件 `contributes.minigame.type` 时，挂载 iframe 加载插件 UI | `ScenePlay.vue` 中 `pluginMinigameView` + `play-plugin-minigame-panel` section |

后端 orchestrator 路由（让 `#野外生存` 命令真的能创建一个 plugin 类型的 miniGame session）属于 **P2 工作**，不在本文档范围内。

## 3. usePluginRuntime composable

文件：`src/composables/usePluginRuntime.ts`

### 暴露的派生数据

```ts
const runtime = usePluginRuntime();

runtime.items.value              // PluginListItem[] - 已启用 + manifest 存在的插件
runtime.sidebarCommands.value    // PluginSidebarCommand[] - 命令面板用的项
runtime.minigameContributes.value // ResolvedPluginMinigame[] - iframe 挂载用
runtime.loading.value            // boolean
runtime.error.value              // string | null
runtime.lastLoadedAt.value       // number

// 操作
await runtime.reload(force?: boolean)  // 30s 节流，force=true 跳过
runtime.clear()

// 工具
runtime.findMinigameByType(type)       // ResolvedPluginMinigame | undefined
runtime.resolveIframeUrl(pluginId, rel) // 拼带 token 的 GET URL
runtime.decodeName(v, fallback)         // 解 manifest.name.{fallback, $t}
```

### 缓存策略

- **不持久化到 localStorage**：每次 ScenePlay 挂载或插件版本号变化时重新拉取。
- **30 秒节流**：`reload()` 默认走缓存，仅在 `pluginRuntimeVersion` 变化（用户增删启停）时强制刷新。
- **单例**：`items` / `loading` 用模块级 ref，多个组件共享同一份。

### PluginSidebarCommand 结构

```ts
interface PluginSidebarCommand {
  id: string;          // 'plugin_<pluginId>_<sourceId>' - 命令面板 id 同空间
  label: string;       // '野外生存'
  desc: string;        // '来自插件：野外生存 ARPG 小游戏'
  icon: string;        // emoji 兜底
  insertText: string;  // '#野外生存 ' - 已拼好前缀和尾随空格
  pluginId: string;    // 'com.toonflow.minigame-field-survival'
  sourceId: string;    // 'field-survival-start' (manifest.contributes.sidebar[].id)
}
```

### ResolvedPluginMinigame 结构

```ts
interface ResolvedPluginMinigame {
  pluginId: string;
  type: string;        // 'field_survival'
  title: string;
  entry: string;       // 'ui/game.html' (manifest 里的相对路径)
  width: number;       // 960
  height: number;      // 640
  fullscreen: boolean; // true
  item: PluginListItem;
}
```

## 4. 命令面板注入

### 现有硬编码（ScenePlay.vue 第 1488 行）

```ts
const baseCommandOptions: CommandOption[] = [
  { id: "mini_game", label: "小游戏", ... },
  { id: "battle", ... },
  ...
];
```

### 改后（computed）

```ts
const commandOptions = computed(() => {
  const list = [...baseCommandOptions];
  if (pluginRuntime.sidebarCommands.value.length > 0) {
    list.push({ id: "_plugin_section", label: "── 插件 ──", desc: "", icon: "🧩" });
    for (const s of pluginRuntime.sidebarCommands.value) {
      list.push({
        id: s.id, label: s.label, desc: s.desc, icon: s.icon,
        insertText: s.insertText, pluginId: s.pluginId, sourceId: s.sourceId,
        isPlugin: true,
      });
    }
  }
  return list;
});
```

### 触发逻辑（selectCommand）

```ts
function selectCommand(cmd) {
  const pluginCmd = cmd as PluginCommandOption;
  if (pluginCmd.isPlugin && pluginCmd.insertText) {
    // 1. 写入输入框（与原 #命令 流程同构）
    store.state.sendText = ... + pluginCmd.insertText + ...;
    commandActive.value = false;
    // 2. nextTick 后自动提交（与 #小游戏 / #战斗 等行为一致）
    nextTick(() => void submit());
    return;
  }
  // 原内置命令：仅写入，不自动发送
}
```

> 设计权衡：插件命令**默认自动提交**，避免「菜单点完还要回车」的认知负担。如需改成只填不送，编辑 `isPlugin` 分支即可。

### 触发时机

- **ScenePlay onMounted**：调用 `pluginRuntime.reload()` 拉取首屏
- **watch pluginRuntimeVersion**：用户在设置里增删启停插件后自动刷新
- **设置弹窗 onPluginManagerChanged**：把 store 的 `pluginRuntimeVersion` +1

## 5. minigame iframe 容器

### 触发条件

`activeMiniGame.gameType` 命中插件 `contributes.minigame.type` 时显示容器：

```ts
const pluginMinigameView = computed(() => {
  const game = activeMiniGame.value;
  if (!game) return null;
  const gt = String(game.gameType || "");
  // 优先匹配 plugin:<id>（推荐协议）
  if (gt.startsWith("plugin:")) {
    const id = gt.slice("plugin:".length);
    const m = pluginRuntime.minigameContributes.value.find(x => x.pluginId === id);
    return m ? { contribute: m, iframeSrc: pluginRuntime.resolveIframeUrl(m.pluginId, m.entry) } : null;
  }
  // 否则按 manifest.type 反查（兼容性模式，要求后端直接用 manifest.type）
  const m = pluginRuntime.findMinigameByType(gt);
  return m ? { contribute: m, iframeSrc: pluginRuntime.resolveIframeUrl(m.pluginId, m.entry) } : null;
});
```

### 模板（ScenePlay.vue mini-game-panel 后面）

```html
<section
  v-if="pluginMinigameView && playMode !== 'setting' && ..."
  class="play-plugin-minigame-panel"
>
  <div class="play-plugin-minigame-panel__head">
    <div class="play-plugin-minigame-panel__title">{{ pluginMinigameView.contribute.title }}</div>
    <div class="play-plugin-minigame-panel__meta">
      来自插件：{{ pluginMinigameView.contribute.pluginId }}
    </div>
  </div>
  <iframe
    class="play-plugin-minigame-panel__iframe"
    :src="pluginMinigameView.iframeSrc"
    :style="{ width: ..., height: ... }"
    sandbox="allow-scripts allow-same-origin allow-forms allow-popups"
    referrerpolicy="no-referrer"
  />
</section>
```

### iframe 安全约束

- **`sandbox`**：禁 top-level navigation / 禁 plugins。允许 scripts + same-origin + forms + popups（用于游戏内可能的表单提交/链接）。
- **资源 URL 带 token**：`/plugin/getAsset?token=...` 走 JWT 中间件鉴权（见 pluginRegistry.ts 的 readPluginAsset）。
- **referrerpolicy="no-referrer"**：防止插件内 iframe 把主站 token/URL 泄露给第三方资源。

### CSS

`styles.css` 新增：
- `.play-plugin-minigame-panel`：圆角面板
- `.play-plugin-minigame-panel__head`：标题区
- `.play-plugin-minigame-panel__iframe`：iframe 容器
- `.play-plugin-minigame-panel__hint`：底部提示

## 6. 前后端协议约定（建议）

### 6.1 命令约定

| 触发方式 | 用户操作 | 后端收到 | 备注 |
|----------|----------|----------|------|
| 菜单点击 | 拼 `#野外生存 ` + 自动 send | `sendMessage` 收到文本 `#野外生存 ` | 与 #小游戏 / #战斗 同构 |
| 直接输入 | 用户键入 `#野外生存 ...` | 同上 | 同构 |

### 6.2 minigame session 协议（P2 待做）

后端 MiniGameAgent 创建插件小游戏 session 时，建议把 `game_type` 设为：

```
plugin:<manifest.id>
```

例如：
```
plugin:com.toonflow.minigame-field-survival
```

这样前端 iframe 容器会用 `plugin:<id>` 前缀精确匹配插件清单。

**兼容模式**：如果后端不知道插件存在，仍可以用 `manifest.contributes.minigame.type`（如 `field_survival`）作为 game_type，前端会按 type 反查。

### 6.3 插件内通信（postMessage）

iframe 内游戏通过 `window.parent.postMessage(...)` 向主界面汇报状态变更。建议协议（参考 tavo）：

```js
// 插件 → 主界面
parent.postMessage({
  type: "toonflow/plugin/action",
  pluginId: "com.toonflow.minigame-field-survival",
  sessionId: "<current session>",
  payload: { kind: "score", value: 120 }
}, "*");

// 主界面 → 插件（监听 message 后转发）
window.addEventListener("message", (e) => {
  if (e.data?.type === "toonflow/plugin/action") {
    store.applyPluginAction(...);
  }
});
```

P3 阶段再做。当前 v1 仅展示静态 iframe。

## 7. 验证步骤

1. 启动后端 `yarn dev`，启动前端 `yarn dev`
2. 登录 admin
3. 设置 → 插件管理 → 上传 `toonflow-field-survival-1.0.0.tpg`
4. 进入任意会话场景（playMode = live）
5. 输入框敲 `#`，看弹出面板底部「── 插件 ──」分组下出现「🎮 野外生存」
6. 点击 → 自动提交 `#野外生存` 到后端
7. 等待后端 MiniGameAgent 创建 `field_survival` 类型的 miniGame session
8. `play-plugin-minigame-panel` section 自动出现并加载 `ui/game.html`

如果第 7 步后端没响应（命令路由未实现），面板不会自动出现，但**菜单里能看见**「野外生存」已经成功。
