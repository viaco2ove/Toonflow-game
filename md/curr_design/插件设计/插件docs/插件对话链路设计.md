# 插件对话链路设计（角色发言器 task-speaker-agent）

> 依据：`toonflow-game-plugins/md/curr_design/toonflow-field-survival/game.md` §对话功能
> 落地插件：`toonflow-field-survival`（城镇 28 个 NPC + 14 个 ally 全部可对话）
> 最后更新：2026-10-05（bsk 端到端实测通过，`--conn` 与「安装后」同一条链路）

---

## 0. 需求原文（game.md §对话功能）

| 需求 | 落地位置 |
|------|---------|
| 触碰角色后头顶显示「聊天」按钮 | 插件前端 `nearChat` + `drawEntity` 头顶气泡 |
| 点击后调用**角色发言器 agent** 发言 | `entry.ts/entry.js` 的 `sys_chat` → `ctx.tsApi.agent.run("task-speaker-agent")` |
| 台词同步到 Toonflow-game-web 聊天框 | `tf_plugin_chat` postMessage → `ScenePlay.vue` |
| 提供「发言 / 继续 / 离开」 | 插件聊天面板三个按钮 |
| 「发言」给 3 个 AI 推荐选项 + 自定义输入 | `mode: "options"` 一次 LLM 调用出 3 条 |
| ally = 故事角色列表；neutral = 地图 NPC；都没有 → 旁白 | entry 侧身份判定（见 §4.2） |
| 野怪是战斗不是对话 | 只有 `side !== "enemy"` 才给聊天按钮 |
| `--conn` 与安装后都要**真实调用大模型** | dev-host 桩把 speaker 代理到 `POST /plugin/agentRun` |

## 1. 链路总览

```
插件 UI（iframe / game.html）
  │  sendTick("sys_chat", { reqId, npcId, npcName, userText, lastResp, mode })
  ↓  postMessage { type:"tf_plugin_tick", action:"sys_chat", params }
宿主前端（ScenePlay.vue / dev-host 桩）
  ↓  POST /plugin/tick { sessionId, pluginId, action:"sys_chat", params }
宿主后端（routes/plugin/tick.ts）
  ↓  executePluginAction → 插件 entry.js（优先）/ entry.ts
插件后端 sys_chat
  ↓  身份判定 + 拼 npcCard
  ↓  ctx.tsApi.agent.run("task-speaker-agent", {...})
PluginAgentRunner（speaker 分支）
  ↓  getPromptByCode("task-speaker-agent") + u.ai.text.invoke   ← 真·大模型
  ↓  写回 s.chatResult = { reqId, ok, mode, speaker, text|options, error }
  ↓  tick 回包 state → 宿主 → postMessage tf_plugin_data → 插件 UI
插件 UI：notifyChatResult(reqId) 唤醒等待中的 Promise
  ↓
台词 push 进聊天面板 + sendChat() → tf_plugin_chat → web 聊天框
```

**三条运行环境走的是同一条链**：

| 环境 | agent 通道 | 是否真 LLM |
|------|-----------|-----------|
| 插件安装后（web / android-h5） | `entry.js` → `ctx.tsApi.agent.run` → `runPluginAgent` | ✅ |
| `npm run debug -- --story X --conn`（dev-host 桩） | 桩的 `agent.run` 转发 `POST /plugin/agentRun` → `runPluginAgent` | ✅ |
| standalone（无宿主，直接开 `ui/game.html`） | `mockHost.ts` 本地桩 | ❌ 标注「离线模拟」 |

## 2. 前端契约（`sendTick("sys_chat")`）

### 2.1 请求参数

```ts
sendTick("sys_chat", {
  reqId:    "chat_<ts>_<rand>",   // ★ 必带：结果配对用
  npcId:    "mapnpc_169",         // 实体 id（mapnpc_<Tiled对象id> / 角色 id）
  npcName:  "矮人比利",            // 显示名（已做身份判定后的名字）
  userText: "你这儿有什么活儿？",   // 玩家本轮说的话；null = 让角色主动开腔
  lastResp: "…",                  // 上一句台词（对话历史）
  mode:     "response" | "options",
});
```

### 2.2 为什么不能用 HTTP 回包取结果

`/plugin/tick` 是**高频轻量接口**（移动/攻击每帧都打），后端回包的 `state` 会被下一帧 tick 的推送覆盖；
而 LLM 调用要 3~15 秒。所以后端把结果写进 **`state.chatResult`**，随下一次 state 推送回来，
前端**按 `reqId` 配对**取回：

```ts
// 发起
const reqId = `chat_${Date.now()}_${Math.random().toString(36).slice(2, 7)}`;
sendTick("sys_chat", { reqId, /* … */ });
const res = await waitChatResult(reqId);   // 45s 超时

// 收到 state 时
function onHostState(d) {
  if (d?.chatResult) notifyChatResult(d.chatResult);
}
```

```ts
const chatResultWaiters: Array<{ reqId: string; resolve: (r: any) => void; timer: number }> = [];
function waitChatResult(reqId: string, timeoutMs = 45000): Promise<any> { /* setTimeout + 队列 */ }
function notifyChatResult(res: any): void { /* 按 reqId 找到 waiter → clearTimeout → resolve */ }
```

### 2.3 `state.chatResult` 结构

```ts
type ChatResult =
  | { reqId: string; ok: true;  mode: "response"; speaker: string; text: string }
  | { reqId: string; ok: true;  mode: "options";  speaker: string; options: string[] }  // 长度 ≤3
  | { reqId: string; ok: false; mode: string; error: string };                          // ★ 失败也必须回包
```

> ⚠️ **失败也必须写回 `chatResult`**（`ok:false` + `error`），否则前端 Promise 永远 pending，
> 表现为「点了聊天一直转圈」。插件侧**不兜底台词**（Game.md 要求真台词，伪造台词比报错更糟），
> 面板顶部显示红色错误提示。

## 3. 后端：`sys_chat` 分支（entry.ts / entry.js 双镜像）

> 铁律：宿主**优先加载 `entry.js`**，两份文件必须同步改。

```ts
case "sys_chat": {
  const npcId = str(params?.npcId, "");
  const npcName = str(params?.npcName, "???");
  const userText = params?.userText as string | null | undefined;
  const lastResp = str(params?.lastResp, "");
  const mode = str(params?.mode, "response");
  const reqId = str(params?.reqId, "");

  // ① 身份判定（见 §4.2）
  // ② 拼 npcCard（见 §4.3）
  // ③ 调 agent
  const result = await context.tsApi.agent.run("task-speaker-agent", {
    npcId, npcName: roleName, npcCard, isNeutral,
    userText: userText ?? null, lastResp: lastResp || null, mode,
    context: { storyDigest: `session:${context.sessionId}`, playerLevel },
  });
  // ④ 剥 ``` 围栏 → 按 mode 解析 → 写 s.chatResult → persistSys
}
```

`mode="options"` 解析策略（容错两级）：

1. `JSON.parse(raw)` 得到数组 → 取前 3 条；
2. 失败则按行拆，去掉 `1. ` / `① ` 之类编号前缀 → 取前 3 行；
3. 仍为空 → `throw new Error("agent 未返回有效选项")`（走 §2.3 的错误回包）。

## 4. agent 侧：`runPluginAgent` 的 speaker 分支

文件：`toonflow-game-app/src/lib/plugins/PluginAgentRunner.ts`

### 4.1 与其它插件 agent 的差异

| | map-gener / shop-gener | **task-speaker-agent** |
|---|---|---|
| 出入参 | JSON 进 / JSON 出（extractJson + sanitize） | **文本进 / 文本出**，不解析 JSON |
| 兜底 | 有 `fallbackMap()` | **无兜底**，失败如实报错 |
| 超时 | 15s | 15s（`AGENT_TIMEOUT_MS`） |

### 4.2 身份判定（谁在说话）

```
有故事角色卡（roles 里命中 id/name）      → 用角色卡身份
否则 实体名 ≠ "" 且 ≠ "NPC"              → 用实体名（城镇地图 NPC 走这条）
否则 调用方传了真名（≠ ""/"???"/"NPC"）   → 用传入名
否则（无卡无名的中立实体）                → 旁白 isNeutral = true
```

> ❗ 坑：`side === "neutral"` **不等于**旁白。城镇地图 NPC 都是 neutral，但它们有 gid、有实体名，
> 必须以自己的身份说话；只有真正的环境/无主实体才是旁白。

### 4.3 npcCard（给模型的角色人设）

故事角色直接用动态角色卡；**地图 NPC 没有卡，用实体信息现拼**，让模型自主演绎：

```ts
{
  id, name, roleType: "ally" | "npc",
  description: entity.desc || entity.dialog || "",
  level, entity_type, gid, mapName, x, y,
}
```

### 4.4 提示词与「格式覆盖」

`task-speaker-agent` 的提示词原本为任务模式设计（输出 `{speaker,content,tone,emotion}` JSON 对象），
插件对话要的是**纯台词 / 纯选项数组**两种形态。若不做覆盖，模型会把两套格式混着输出（既给对象又给数组），
前端解析不出干净结果。做法：在 system 尾部追加本轮格式覆盖。

```ts
const formatOverride = mode === "options"
  ? "\n\n【本轮输出格式覆盖】忽略上文任何 JSON 对象格式要求。本轮只输出一个 JSON 字符串数组，包含 3 个玩家发言选项…"
  : "\n\n【本轮输出格式覆盖】忽略上文任何 JSON 对象格式要求。本轮只输出纯台词文本本身（1-3 句）…";
```

输出清洗（两道）：

```ts
const unfenced = rawText.replace(/^\s*```[a-zA-Z]*\s*/, "").replace(/\s*```\s*$/, "").trim();
const text = unfenced.replace(/^"([\s\S]*)"$/, "$1").trim();   // 剥首尾成对引号
```

### 4.5 注册一个新插件 agent（三步）

1. `src/agents/plugins.prompts.ts` → `PLUGIN_AGENT_PROMPT_CODES` 加项 + `pluginAgentPromptCode()` 加 case；
2. `src/lib/plugins/PluginAgentRunner.ts` → 加输入 interface + 分支（文本型 or JSON 型）；
3. 提示词默认值写进 `DEFAULT_PROMPTS`（DB `customValue` 可覆盖，设置页可改）。

> 改完**必须重启后端进程**（`tsx src/app.ts` 非 watch 模式），否则新路由/新 agent 不生效。

## 5. 调试

### 5.1 后端直连（不启前端）

```bash
TOKEN=$(grep '^auth_token=' .env | cut -d= -f2-)
curl -s -X POST http://localhost:60002/plugin/agentRun \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"agentName":"task-speaker-agent","input":{"npcId":"mapnpc_169","npcName":"矮人比利","mode":"response","userText":"你这儿有什么活儿？"}}'
# → { code:200, data:{ ok:true, output:{ text:"…" } } }
```

`POST /plugin/agentRun` 存在的意义：dev-host 桩跑在浏览器里、没有 LLM 通道，
必须让后端代跑 `runPluginAgent`，才能验证「安装后由 entry.ts 直连大模型」的同一条链。

### 5.2 前端 E2E 钩子（`window.__FS_DEBUG__`）

生产构建下 Vue 内部实例在隔离世界读不到（`__vue_app__._instance` 不可访问），
所以插件侧暴露**只读调试钩子**供 bsk / 控制台巡检：

```js
__FS_DEBUG__.chat.open("mapnpc_169", "矮人比利");  // 发起一轮真 LLM 对话
__FS_DEBUG__.chat.genOptions();                    // 请求 3 个发言选项（注意：不叫 options）
__FS_DEBUG__.chat.messages / .options / .error / .pending
__FS_DEBUG__.state.entities                        // 含 mapnpc_* / ally
```

### 5.3 常见故障

| 现象 | 根因 | 处理 |
|------|------|------|
| 点了聊天一直转圈 | 未回推 `chatResult`（忘了写 / 后端没重启） | 后端 `s.chatResult = { reqId, ok:false, error }` 必须落 |
| 台词是假/兜底文案 | 走了 standalone mock | 用 `--conn` 或安装后入口 |
| 选项里混进 `{"speaker":...}` | 没做格式覆盖 | §4.4 |
| `未知插件 agent: task-speaker-agent` | 没在 `pluginAgentPromptCode` 注册 | §4.5 + 重启后端 |
| NPC 张口就是「旁白」 | `side==="neutral"` 被一律当旁白 | §4.2 |
