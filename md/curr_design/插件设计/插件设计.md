# Toonflow-Game 插件系统设计方案

> 参考 Tavo 插件架构，为 Toonflow-Game 设计的插件系统方案

## 一、设计目标

| 目标 | 说明 |
|------|------|
| **小游戏扩展** | 为用户提供更多可嵌入的互动小游戏 |
| **UI 增强** | 面板、侧边栏、悬浮按钮等 UI 扩展 |
| **AI 能力增强** | 记忆管理、事件编排、角色状态等 Agent 能力 |
| **用户隔离** | 插件安装与用户绑定，保障隐私与安全 |

## 二、插件包格式 (.tpg)

沿用 Tavo 的 `.tpg` 格式（本质是 zip 压缩包），保持与 Tavo 生态的兼容性。

### 2.1 插件目录结构

```
toonflow-field-survival/     # 插件源码目录（最终打包为 .tpg）
├── manifest.json            # 插件元数据（必须）
├── entry.js                 # 前端入口脚本（minigame 插件必须）
├── entry.ts                 # 后端 TypeScript 入口（插件小游戏必须，编译为 entry.js）
├── ui/                      # 前端 UI 资源
│   ├── game.html           # 小游戏 HTML（iframe 加载）
│   ├── styles.css          # 样式文件
│   └── assets/             # 静态资源
├── vue/                     # Vue 组件目录（可选，用于 Vue 改造后的游戏 UI）
├── locales/                 # 国际化资源
│   ├── zh-CN.json
│   └── en.json
├── cover.png                # 插件封面（可选）
└── README.md                # 插件说明（可选）
```

### 2.2 manifest.json 规范

```json
{
  "id": "com.toonflow.minigame-field-survival",
  "name": "野外生存",
  "version": "1.0.0",
  "author": "Toonflow Team",
  "description": "在荒野中生存，寻找食物和水源，抵御野兽袭击，挑战极限生存天数。",
  "main": "entry.ts",
  "contributes": {
    "minigame": {
      "type": "field_survival",
      "title": "野外生存",
      "width": 480,
      "height": 640,
      "entry": "ui/game.html"
    },
    "sidebar": [
      {
        "id": "field-survival-cmd",
        "label": "野外生存",
        "command": "#野外生存"
      }
    ]
  }
}
```

**字段说明：**

| 字段 | 必须 | 说明 |
|------|------|------|
| `id` | ✅ | 反向域名格式唯一标识 |
| `name` | ✅ | 插件显示名称 |
| `version` | ✅ | 语义化版本 |
| `contributes.minigame` | 小游戏插件必须 | 小游戏配置 |
| `contributes.minigame.type` | ✅ | 小游戏类型标识（如 `field_survival`），前端 iframe 按此匹配 |
| `contributes.minigame.entry` | ✅ | iframe 加载的 HTML 入口（相对插件根目录） |
| `contributes.sidebar` | 推荐 | 侧边栏命令，`command` 字段（以 `#` 开头）会被后端扫描注册 |
| `main` | 小游戏插件必须 | 后端入口文件（`entry.ts`） |

> ⚠️ **已废弃字段**：`backendEntry`（原 Python 后端入口）、`specVersion`、`permissions`、`panel`、`settings`、`dependencies`，Toonflow 当前实现中不再使用。

## 四、数据库设计

### 4.1 实际实现：t_plugin 单表

> ⚠️ **实现说明**：实际落地时合并为单表 `t_plugin`（见 `src/migrations/20260921_000001_add_plugin_table.js`），不再使用原方案的三表结构。

```sql
CREATE TABLE t_plugin (
  id            INTEGER PRIMARY KEY,
  userId        INTEGER NOT NULL,           -- 用户隔离（每用户一套安装）
  pluginId      TEXT NOT NULL,              -- manifest.id
  name          TEXT,                       -- manifest.name（fallback 字符串）
  version       TEXT,                       -- manifest.version
  author        TEXT,
  description   TEXT,
  dir           TEXT NOT NULL,              -- 插件文件目录名
  entry         TEXT,                       -- 前端入口（manifest.entry）
  backendEntry  TEXT,                       -- 后端入口（manifest.backendEntry，可空）
  manifestJson  TEXT NOT NULL,              -- 完整 manifest JSON 快照
  enabled       INTEGER DEFAULT 1,          -- 1 启用 / 0 禁用
  status        TEXT DEFAULT 'installed',   -- installed | disabled | error
  installedAt   BIGINT,                     -- 安装时间 ms
  updatedAt     BIGINT                      -- 更新时间 ms
);
CREATE UNIQUE INDEX idx_plugin_user_plugin ON t_plugin (userId, pluginId);
```

**字段说明：**

| 字段 | 说明 |
|------|------|
| `userId` | 用户隔离，不同用户安装同一插件各有一行 |
| `pluginId` | manifest 中的插件唯一标识 |
| `dir` | 插件文件实际存放目录（相对于插件根目录） |
| `manifestJson` | manifest 完整快照，供 `PluginExecutor.scanPluginCommands` 直接解析 |
| `enabled` | 运行时启用标志，扫描命令时只取 `enabled=1 && status='installed'` 的记录 |
| `status` | 生命周期状态 |

**插件文件存储目录：**

```
<数据根>/Toonflow-game/plugins/
└── <userId>/
    └── <pluginId>/
        ├── manifest.json
        ├── entry.js          ← tsc 编译产物
        ├── entry.ts          ← 插件源码（TypeScript）
        ├── ui/
        │   └── game.html     ← iframe 入口
        ├── vue/              ← Vue 改造目录（可选）
        └── locales/
            └── zh-CN.json
```

- 用户隔离：每用户独立目录
- 安装时先解压到 `.tmp/<timestamp>-<uuid>/`，定位 manifest 所在目录，再原子重命名到目标位置
- 卸载时先改名（避免 Windows 文件锁），再删除目录

class PluginLoader {
  private loadedPlugins: Map<string, PluginInstance> = new Map();

  // 加载插件
  async loadPlugin(plugin: PluginMeta): Promise<PluginInstance> {
    // 1. 获取插件文件列表
    // 2. 加载 entry.js
    // 3. 创建沙箱上下文
    // 4. 执行入口函数
    // 5. 注册 UI 组件
  }

  // 卸载插件
  unloadPlugin(pluginId: string): void {
    const instance = this.loadedPlugins.get(pluginId);
    if (instance?.cleanup) {
      instance.cleanup();
    }
    this.loadedPlugins.delete(pluginId);
  }
}

```javascript
// 猜数字游戏 - entry.js
class GuessNumberGame {
  constructor(ctx) {
    this.ctx = ctx;
    this.state = {
      target: Math.floor(Math.random() * 100) + 1,
      attempts: 0,
      maxAttempts: 10,
      gameOver: false,
      won: false
    };
  }

  // 渲染游戏界面
  render() {
    return `
      <div class="guess-game">
        <h3>🎯 猜数字 (1-100)</h3>
        <p>剩余次数: ${this.state.maxAttempts - this.state.attempts}</p>
        <input type="number" id="guess-input" min="1" max="100" />
        <button onclick="guessNumber(this.ctx)">猜！</button>
        <div id="guess-result"></div>
        <button onclick="this.ctx.hidePanel()">关闭</button>
      </div>
    `;
  }

  // 处理猜测
  guess(number) {
    this.state.attempts++;

    if (number === this.state.target) {
      this.state.won = true;
      this.state.gameOver = true;
      return { result: 'correct', message: `🎉 猜对了！答案就是 ${number}` };
    } else if (number < this.state.target) {
      return { result: 'hint', message: '📈 太小了，再试试！' };
    } else {
      return { result: 'hint', message: '📉 太大了！' };
    }
  }

  cleanup() {
    // 清理资源
  }
}

// 全局工厂函数
function createPlugin(ctx) {
  return new GuessNumberGame(ctx);
}
```

## 八、插件执行器（PluginExecutor）

> 文件：`src/lib/PluginExecutor.ts`，TypeScript 实现，零子进程。

### 8.1 PluginExecutor 核心职责

```
PluginExecutor 职责：
1. scanPluginCommands(userId)   — 扫描已启用插件的 sidebar.command，缓存 command → ctx
2. findPluginByCommand(cmd)     — 按命令查找插件上下文
3. loadEntryModule(pluginDir)   — 动态 import() entry.js（file:// URL，ESM，模块缓存）
4. executePluginAction()        — 调用 entry.ts · handle_action 并返回 HandleActionResult
```

### 8.2 核心 API

```typescript
// 扫描用户所有已启用插件，收集 contributes.sidebar[].command
await scanPluginCommands(userId: number): Promise<void>

// 根据命令文本查找匹配的插件上下文
findPluginByCommand(command: string): PluginGameContext | null

// 执行插件的 handle_action
await executePluginAction(
  ctx: PluginGameContext,
  action: string,
  params: HandleActionParams,
  state: PluginGameState
): Promise<HandleActionResult>

// 获取所有已扫描的命令（调试用）
getAllPluginCommands(): string[]
```

### 8.3 类型定义

```typescript
interface PluginGameContext {
  pluginId: string;     // manifest.id
  pluginDir: string;    // 插件目录绝对路径
  manifest: PluginManifest;
}

interface HandleActionResult {
  code: number;         // 0=成功，非0=失败
  message: string;
  state: PluginGameState;      // 返回 state（系统自动持久化）
  response?: string;           // 人类可读回复（旁白/日志）
  actions?: string[];          // 当前可选动作列表（前端渲染用）
}
```

### 8.5 数据流

```
用户输入 "#野外生存"
  ↓
MiniGameController.handleMiniGameTurn
  ↓
detectGameTrigger (先扫 RULEBOOKs，未命中则扫插件命令)
  ↓
PluginExecutor.scanPluginCommands(userId)  ← 扫所有已启用插件 sidebar.command
  ↓
findPluginByCommand("#野外生存") → PluginGameContext
  ↓
RULEBOOKS.plugin.setup (写入 public_state.plugin_type = "field_survival")
  ↓
前端 ScenePlay 收到 meta.miniGame.publicState
  ↓
pluginMinigameView.iframeUrl = pluginAssetUrl(pluginId, entry)
  ↓
iframe 加载 ui/game.html
  ↓
iframe 内游戏 → POST /api/miniGame/action → 后端
  ↓
PluginExecutor.executePluginAction(ctx, action, params, state)
  ↓
entry.ts · handle_action(action, params, state, context)
```

### 8.6 命令注册与扫描机制

**记录地点：** manifest.json — `contributes.sidebar[].command`

```json
{
  "contributes": {
    "sidebar": [
      {
        "id": "field-survival-cmd",
        "label": "野外生存",
        "command": "#野外生存"
      }
    ]
  }
}
```

- `command` 必须以 `#` 开头
- `MiniGameController.detectGameTrigger` 先扫 RULEBOOKS，未命中则调用 `scanPluginCommands`
- 命中后返回 `{ gameType: 'plugin', pluginId, pluginType, source: 'plugin' }`
- `RULEBOOKS.plugin` 是内置通杀 rulebook，从 `(root as any)._pluginManifest` 取 manifest

**常见问题：**

| 问题 | 答 |
|------|---|
| 已禁用插件的命令能触发吗？ | 不能。`scanPluginCommands` 只扫 `enabled && status === 'installed'` 的插件 |
| 多个插件声明同一命令怎么办？ | 后端先到先得；建议插件作者避免命令冲突 |
| 如何调试扫描结果？ | `PluginExecutor.getAllPluginCommands()` 返回所有已扫命令 |

### 8.7 entry.ts 标准契约

```typescript

  action: string,           // 'init' | 'start' | 'find_food' | 'attack' | ...
  params: Record<string, unknown>,
  state: Record<string, unknown>,    // 上一次返回的 state（自动持久化）

  message: string;

  response?: string;       // 给前端的纯文本回复（旁白/日志）

}>;
```

## 九、插件安全模型

### 9.1 沙箱隔离

| 限制项 | 说明 |
|--------|------|
| **网络访问** | 禁止直接网络请求，必须通过 `ctx.fetch()` |
| **存储访问** | 仅允许读写插件专属的 storage |
| **文件访问** | 禁止访问文件系统 |
| **代码执行** | 前端使用 iframe 沙箱，后端使用 subprocess 隔离 |

### 9.2 权限审批

```json
{
  "permissions": {
    "ui": { "level": "allow" },
    "game_state": { "level": "prompt" },  // 需要用户确认
    "ai_generate": { "level": "prompt", "maxTokens": 500 },
    "network": { "level": "deny" }
  }
}
```

## 附录 B: manifest.json 当前实现字段

```typescript
interface PluginManifest {
  id: string;                    // 唯一标识 (反向域名)
  name: string;                  // 显示名称（字符串，非 LocalizedString）
  version: string;               // 语义化版本
  author?: string;
  description?: string;
  main?: string;                 // 后端入口（entry.ts）
  contributes?: {
    minigame?: {
      type: string;              // 小游戏类型标识
      title?: string;
      width?: number;
      height?: number;
      entry?: string;            // iframe 入口（ui/game.html）
    };
    sidebar?: Array<{
      id: string;
      label: string;
      command?: string;          // 以 # 开头的命令
      icon?: string;
    }>;
  };
}
```

> ⚠️ **已废弃字段**：`specVersion`、`permissions`、`panel`、`settings`、`dependencies`、`LocalizedString`、`backendEntry`。这些字段在 Toonflow 当前实现中不再使用。
