# 章节设计

## 1. 章节结构

章节内容使用 Markdown 格式，通过二级标题(`##`)来划分不同的阶段(Phase)。

### 1.1 示例结构

```markdown
## 全局状态（仅用户可见）
@系统：你已被卷入【混沌裂隙】...

## 场景开始
@旁白：破碎的星辰残骸漂浮在虚空之中...

## 🧩 用户行动1（被编排触发）
@系统（仅对用户）：你被冲击波掀飞...

## 主线推进
@旁白：战斗愈发激烈...

## 🧩 用户行动2（异常感知）
@系统（仅对用户）：⚠️ 检测到异常...

## 非事件：时间停滞
@旁白：爆炸达到顶点...
```

## 2. Phase 对象结构

```typescript
interface ChapterRuntimePhase {
  id: string;                      // phase_1_全局状态
  label: string;                   // "全局状态（仅用户可见）"
  kind: "opening" | "scene" | "user" | "fixed";  // 阶段类型
  targetSummary: string;           // 阶段目标摘要
  userNodeId: string | null;       // 用户节点ID（如果是用户行动阶段）
  allowedSpeakers: string[];       // 允许发言的角色列表
  nextPhaseIds: string[];          // 下一个阶段的候选ID列表
  defaultNextPhaseId: string | null;  // 默认下一个阶段ID
  requiredEventIds: string[];      // 前置要求事件ID
  completionEventIds: string[];    // 完成时触发的事件ID
  advanceSignals: string[];        // 推进信号
  relatedFixedEventIds: string[];  // 关联的固定事件ID
}
```

## 3. 章节内容转换为事件的流程

### 3.1 内容解析

```
章节Markdown内容
    ↓
通过 ## 标题分割 → 多个 section
```

### 3.2 Phase 生成

```
每个 section → 转换为 ChapterRuntimePhase 对象
    ↓
包含 id/label/kind/targetSummary 等字段
```

### 3.3 状态存储

```
所有 Phase 存储在章节的 runtimeOutline 字段（JSON格式）
```

### 3.4 运行时读取

```
根据 progress.phaseId 从 state 中找到当前 Phase
```

### 3.5 事件构建

```
当前 Phase → 构建 currentEvent 上下文
    ↓
包含 eventIndex/eventKind/eventSummary 等
```

### 3.6 AI 调用

```
将 currentEvent 信息打包成 payload → 传递给编排师 AI
```

## 4. 关键函数

### 4.1 extractRuntimeSections

从章节内容中提取所有 section：

```typescript
function extractRuntimeSections(input: unknown): Array<{ heading: string; body: string }>
```

- 通过正则表达式 `/^##\s*(.+)$/gm` 匹配所有二级标题
- 每个标题之间的内容作为一个独立的 section

### 4.2 readCurrentRuntimeEventContext

读取当前运行时事件上下文：

```typescript
function readCurrentRuntimeEventContext(chapter: any, state: JsonRecord): {
  eventIndex: number;
  eventKind: RuntimeCurrentEventState["kind"];
  eventFlowType: "introduction" | "chapter_content" | "chapter_ending_check" | "free_runtime";
  eventSummary: string;
  eventFacts: string[];
  eventMemorySummary: string;
  eventMemoryFacts: string[];
  eventStatus: RuntimeCurrentEventState["status"];
}
```

## 5. Phase 类型

| 类型 | 说明 |
|------|------|
| `opening` | 开场阶段 |
| `scene` | 场景阶段 |
| `user` | 用户行动阶段 |
| `fixed` | 固定事件阶段 |

## 6. 事件流转机制

ChapterProgressEngine 负责管理 Phase 之间的流转：

```typescript
// 查找下一个可执行的 Phase
for (let index = 0; index < outline.phases.length; index += 1) {
  const phase = outline.phases[index];
  if (isPhaseCompleted(completedEvents, phase.id)) {
    continue;  // 已完成的 Phase 跳过
  }
  if (!arePhaseRequirementsMet(completedEvents, phase)) {
    continue;  // 前置条件不满足的 Phase 跳过
  }
  return { phase, phaseIndex: index };  // 返回第一个可执行的 Phase
}
```

## 8. 总结

| 概念 | 说明 |
|------|------|
| 一个 Phase = 一个事件 | 在编排流程中 |
| 事件流转 | 通过 ChapterProgressEngine 管理 Phase 之间的跳转 |
| AI 提示词 | 编排师收到的是当前 Phase 的摘要和上下文信息，而非完整章节内容 |
| 条件判断 | 支持前置依赖和完成条件检测 |
