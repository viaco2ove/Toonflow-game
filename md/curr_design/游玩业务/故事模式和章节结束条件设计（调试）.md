# 故事模式和章节结束条件设计（调试）

## 1. 概述

故事模式决定了章节如何结束以及玩家的进度如何推进。本文档描述设计原理和调试方法。

## 2. 故事模式类型

### 2.1 线性模式

- 按顺序推进章节
- 章节之间有强依赖
- 必须完成当前章节才能进入下一章节

### 2.2 分支模式

- 章节之间有分支
- 玩家选择影响后续章节
- 不同分支有不同结局

### 2.3 自由模式

- 无固定结束条件
- AI 动态生成事件
- 玩家主导剧情方向

## 3. 章节结束条件

### 3.1 固定结束条件

预先定义的结束条件，满足后章节自动结束：

```json
{
  "success": "玩家成功说服萧炎加入队伍",
  "failure": "玩家与萧炎发生战斗且战败"
}
```

### 3.2 动态结束条件

由 AI 编排师根据剧情进展动态判断：
- 关键事件完成
- 关系达到特定阈值
- 特定角色状态变化

### 3.3 条件格式

```typescript
// 结构化条件
{
  "type": "equals",
  "field": "state.relationship.xiaoyan",
  "value": "friend"
}

// 自然语言条件
"玩家成功说服萧炎"

// 逻辑组合
{
  "type": "and",
  "conditions": [
    { "type": "equals", "field": "state.flags.team_xiaoyan", "value": true },
    { "type": "gt", "field": "state.player.level", "value": 5 }
  ]
}
```

## 4. 章节状态流转

```
idle → active → waiting_input → completed
         ↓
    chapter_completed / failed
```

| 状态 | 说明 |
|------|------|
| `idle` | 未开始 |
| `active` | 进行中 |
| `waiting_input` | 等待用户输入 |
| `completed` | 已完成 |
| `chapter_completed` | 章节成功结束 |
| `failed` | 章节失败结束 |

## 5. 调试方法

### 5.1 调试模式 vs 会话模式

| 模式 | 说明 |
|------|------|
| Debug 模式 | 无状态，用于调试和开发 |
| Session 模式 | 有状态，支持存档、回溯 |

### 5.2 调试端点

- `GET /game/getSession`：获取会话详情，检查章节状态
- `POST /game/orchestration`：支持 debug 模式测试编排
- `POST /game/previewRuntimeOutline`：预览运行时大纲

### 5.3 常见调试问题

**问题 1：章节不结束**
- 检查 `endingRules` 是否正确配置
- 检查 `completionCondition` 是否满足
- 查看 `completedEvents` 列表

**问题 2：章节提前结束**
- 检查 `evaluateCondition` 函数逻辑
- 检查条件表达式是否正确

**问题 3：动态事件不生成**
- 检查自由章节配置
- 检查 AI 编排师返回

### 5.4 日志查看

关键日志标签：
- `chapter_progress`：章节进度变化
- `trigger_hit`：触发器命中
- `event_complete`：事件完成
- `orchestration`：编排结果
- `memory_refresh`：记忆刷新
