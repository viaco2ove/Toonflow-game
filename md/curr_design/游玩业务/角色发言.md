# 角色发言设计

## 1. 概述

角色发言（Speaker）是 AI 故事系统的输出层，负责将编排结果转化为用户可见的台词。

## 2. 三档发言机制

### 2.1 T0：模板直出

**适用场景**：
- 旁白环境补句
- 万能角色/路人起哄
- 明显功能性推进句
- 已有强规则的阶段过渡句

**特点**：
- 不调用大模型
- 直接根据 `speaker + motive + phase` 用模板拼装
- 目标 50~200ms 内出结果

**示例**：
```
旁白：(练武场的哄笑声仍未停歇，几道目光在你与萧炎之间来回扫动)
某男子：(抱着胳膊冷笑一声) 怎么，不敢接话了？
```

### 2.2 T1：轻量模型

**适用场景**：
- 普通 NPC
- 泛旁白
- 万能角色临演
- 非关键角色的过场发言

**特点**：
- 用低延迟模型
- 严格短上下文
- 目标 1~3 秒

### 2.3 T2：高质量模型

**适用场景**：
- 萧炎、纳兰嫣然、薰儿等关键角色
- 用户首次建立关系
- 关键冲突
- 高价值章节节点

**特点**：
- 允许更高质量
- 允许更长一点的动态上下文
- 目标 3~8 秒

## 3. 极简上下文设计

### 3.1 当前问题

当前 speaker 输入仍然会带：
- 世界简介
- 角色参数卡压缩版
- 故事状态摘要
- 最近多轮对话
- 其他可见角色

这对"出一句话"来说仍然偏重。

### 3.2 最小 payload 设计

speaker 只保留五块：
1. 当前说话人最小资料
2. 当前动机
3. 当前阶段标签
4. 最近 2~3 条必要对话
5. 当前用户最新输入

**禁止**：
- 长世界简介
- 长故事背景摘要
- 大段角色参数卡
- 超过 3 条以上最近对话
- 大量"其他可见角色"

### 3.3 动态缓存接口

```typescript
type SessionDynamicDigest = {
  currentPhaseId: string;
  currentConflict: string;
  currentGoal: string;
  keyFacts: string[];
  relationChanges: string[];
  taskChanges: string[];
  itemChanges: string[];
  visibleFocusRoles: string[];
  updatedAt: number;
};
```

## 4. 发言策略路由器

```typescript
type SpeakerModeDecision = {
  mode: "template" | "fast" | "premium";
  voiceMode: "skip" | "async" | "immediate";
  memoryMode: "skip" | "async";
  reason: string;
};
```

- `template`：主要给旁白、万能角色、功能性补句
- `fast`：给普通 NPC 和普通过场
- `premium`：只给关键角色与关键节点

## 5. 语音链路

### 5.1 语音不能阻塞正文首屏

正文必须先落。

语音统一分两种：
- `immediate`：当前消息刚落库就异步请求语音
- `deferred`：用户停留时再请求

### 5.2 旁白/万能角色优先走标准音色

因为这类内容本来就是低成本内容：
- 不需要每轮都跑复杂克隆链
- 优先走标准预设音色
- 进一步减少等待

## 6. 验收指标

- T0 模板：<200ms 内返回正文
- T1 轻量：1~3 秒
- T2 高质量：3~8 秒
- 前端长请求误报超时：降到接近 0
- 不出现"角色说错人"
- 不出现"模型代替用户说台词"
