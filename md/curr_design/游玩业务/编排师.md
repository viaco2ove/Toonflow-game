# 编排师设计

## 1. 概述

编排师（NarrativeOrchestrator）是 AI 故事系统的核心引擎，负责决定"谁来发言、说什么、状态如何变化"。

## 2. 核心职责

1. **AI 提示词编排**：构建发送给大模型的 prompt
2. **记忆提示注入**：将记忆摘要注入上下文
3. **轮次状态管理**：追踪当前轮次状态
4. **发言者路由**：决定下一位 speaker
5. **叙事计划执行**：执行叙事计划并更新状态

## 3. 编排流程

```
用户输入
    ↓
addMessage (写日志)
    ↓
RuleOrchestrator（规则优先决定 speaker）
    ↓
AI Orchestrator（规则无法决定时才调用）
    ↓
Speaker Mode Router（T0模板/T1轻量/T2高质量）
    ↓
streamlines (流式生成台词)
    ↓
commitNarrativeTurn (提交轮次)
    ↓
voice async (异步语音生成)
```

## 4. 规则编排器 (RuleOrchestrator)

### 4.1 什么时候直接绕过 AI 编排师

满足以下任一条件时，规则直接给出下一位 speaker：
1. 当前 phase 明确只有一个允许角色
2. 当前 phase 的默认流向已经固定，且上一轮刚好命中其完成信号
3. 当前轮是固定模板路人/旁白补一句
4. 当前已经到用户节点，必须 `awaitUser=true`
5. 当前轮只是"补一个环境反应"而非真实决策

### 4.2 什么时候才调用 AI 编排师

只在这些情况下调用：
1. 当前 phase 允许多个角色，且规则无法决定谁更自然
2. 当前轮涉及用户态度、阵营、关系、任务走向等不确定性
3. 当前轮需要在多个关键角色之间决定谁接话
4. 当前轮需要根据近几轮动态局势决定"谁更适合推进"

### 4.3 输出格式

```json
{
  "role": "萧炎",
  "roleType": "npc",
  "motive": "继续挑衅萧家子弟，同时逼迫异天表态",
  "awaitUser": false,
  "nextRole": "某男子",
  "nextRoleType": "npc",
  "decisionSource": "rule",
  "confidence": "high"
}
```

## 5. AI 编排师 (AI Orchestrator)

当规则无法决定时才调用，负责：
1. 根据完整上下文决定最优下一位 speaker
2. 生成发言动机
3. 评估是否需要触发记忆更新
4. 判断章节进度

## 6. 当前事件数据结构

AI 编排师输入的 `current_event` 需要包含当前阶段的详细信息：

```typescript
interface CurrentEventInput {
  index: number;              // 事件索引
  kind: string;               // 事件类型 (scene/user/fixed)
  flow: string;               // 流程类型 (chapter_content)
  status: string;             // 事件状态 (active/waiting_input/completed)
  summary: string;            // 带状态标记的摘要 "[s]阶段1 → [i]阶段2 → []阶段3"
  facts: string[];            // 事件关键信息
  memory_summary: string;     // 记忆摘要
  memory_facts: string[];     // 记忆事实
  currStageIndex: number;     // 当前阶段索引
  currStageSummary: string;   // 当前阶段摘要（用于编排决策）
}
```

**示例**：
```json
{
  "current_event": {
    "index": 2,
    "kind": "scene",
    "flow": "chapter_content",
    "status": "active",
    "summary": "[s]黑术暗影君王的窥探 → [s]旁白引导剧情 → [i]遇见与交流",
    "facts": [
      "当前事件为遇见与交流，要求用户发言5次后进入下一阶段",
      "用户已累计发言3次"
    ],
    "memory_summary": "",
    "memory_facts": [],
    "currStageIndex": 2,
    "currStageSummary": "随机遇见各种NPC，聊天5轮对话后进入下个事件，用户发言5次"
  }
}
```

## 7. 最近对话数据结构

`recent_dialogue` 数组需要包含每条台词的事件/阶段标记，帮助编排师判断台词归属：

```typescript
interface RecentDialogueItem {
  role: string;
  roleType: string;
  eventType: string;
  content: string;
  // 事件/阶段标记
  event_index: number | null;           // 所属事件索引
  stage_index: number | null;           // 所属阶段索引
  role_num_speech_curr_event: number;   // 该角色在当前事件的发言次数
  role_num_speech_curr_stage: number;   // 该角色在当前阶段的发言次数
}
```

**示例**：
```json
[
  {
    "role": "薰儿（萧薰儿|古薰儿）",
    "roleType": "npc",
    "eventType": "on_orchestrated_reply",
    "content": "敢问阁下是迷途落在此处的旅人吗？",
    "event_index": 2,
    "stage_index": 2,
    "role_num_speech_curr_event": 1,
    "role_num_speech_curr_stage": 1
  },
  {
    "role": "用户",
    "roleType": "player",
    "eventType": "on_message",
    "content": "是的。能否告诉我这里是什么地方",
    "event_index": 2,
    "stage_index": 2,
    "role_num_speech_curr_event": 1,
    "role_num_speech_curr_stage": 1
  }
]
```

## 8. 关键设计原则

1. **规则优先**：规则能决定的直接产出，不调用 AI
2. **分级生成**：不同角色走不同档位（T0/T1/T2）
3. **异步处理**：记忆和语音不阻塞首屏返回
4. **状态缓存**：动态上下文按需加载，避免重复塞上下文

## 9. 与其他模块的关系

- **ChapterProgressEngine**：提供 phase 图约束
- **TriggerEngine**：执行触发器动作
- **TaskProgressEngine**：判定任务变化
- **SpeakerRouteEngine**：发言路由
- **MiniGameController**：小游戏时暂停主线编排
