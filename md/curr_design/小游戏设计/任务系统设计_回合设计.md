# 任务系统设计 — 回合设计

> **任务系统是小游戏的一种**（gameType="task"），但回合行为与挖矿/钓鱼/战斗等结算型小游戏完全不同。
> 走小游戏标准链路：`/game/orchestration/minigame` → `/game/streamlines` → `/game/streamvoice`

---

## 1. 与其他小游戏的差异（核心）

| 维度 | 普通小游戏（挖矿/战斗/钓鱼） | **任务（task）** |
|------|--------------------------|--------------------------|
| 阶段（phaseOrder） | 多阶段固定流程（如 `勘察→挖掘→风险→搬运→结算`） | **单阶段**：`active → settling` |
| 触发命令 | `#挖矿` / `#战斗` 等固定命令 | `#任务:xxx` 命令 + AI 意图分析师识别 |
| applyAction | 在 `MiniGameController.applyAction` 中按规则处理用户输入 | **透传**（`task_passthrough`），不拦截普通输入 |
| 推进方式 | 按规则 step + 回合状态机 | **依赖编排师** 解释用户行动并由旁白回应 |
| 结算时机 | 阶段达到 `settling` 时自动结算 | **由 AI 判断**任务是否成功/失败（每轮检查） |
| 选项 | `options()` 给出按钮选项 | **空数组**（用户自然语言输入） |
| 退出 | `#退出` | `#退出` |

**关键设计决策**：

> 任务面板只复用小游戏容器**展示信息**，不通过 MiniGameController 初始化正式任务内容；任务推进**不在小游戏控制器里结算**，applyAction 只保留兜底说明。
> 真正的任务推进 = 旁白对用户输入的回应 + AI 评估是否触达成功/失败条件。

---

## 2. 回合类型清单

任务系统涉及 6 种回合类型：

| 回合类型 | 触发条件 | 事件类型 | 谁说话 |
|---------|---------|---------|--------|
| **用户进入任务回合** | 用户输入 `#任务:xxx` 或 AI 识别 create_task | `on_mini_game_start` | （无） |
| **任务开场回合** | 任务创建成功，旁白介绍任务目标 | `on_mini_game_start` | 旁白 |
| **用户行动回合** | 用户输入推进任务的自然语言（"先去找王明"） | `on_message` | 用户 |
| **旁白推进回合** | 旁白回应用户行动，描述场景/结果 | `on_orchestrated_reply` | 旁白 / NPC |
| **任务完成回合** | AI 判定任务成功/失败 | `on_mini_game_finish` | 旁白（结算文案） |
| **任务退出回合** | 用户输入 `#退出` | `on_mini_game_abort` | 旁白（退出文案） |

## 4. 状态机详细规格

### 4.1 任务 state 字段

#### `state.player.parameterCardJson`（参数卡）

```typescript
{
  executing_task: {                    // 当前执行的任务（互斥，1 个）
    title: "【自由任务】寻找失联舍友",
    category: "自由任务",
    objective: "在诡异校园范围内找到失联的舍友",
    process: ["..."],
    successConditions: ["..."],
    failureConditions: ["..."],
    status: "doing"                    // doing / completed / failed / aborted
  } | null,                            // 任务结束/退出时为 null

  taskList: [                          // 所有任务历史 + 当前进行中
    { task_id, title, category, objective, status, createdAt, updatedAt },
    ...
  ],

  activeTaskId: "task_xxxxx" | null,   // 当前 active 任务的 task_id
}
```

#### `state.miniGame`（任务面板复用）

```typescript
{
  rulebook: { gameType: "task", displayName: "任务", version: "1.0" },

  session: {
    game_type: "task",
    status: "active" | "aborted" | "finished",
    phase: "执行中",
    round: 1,
    event_index: 3,
    can_quit: true,
    public_state: {                    // 用于面板展示
      task_title, task_category, task_description,
      current_objective, process_steps,
      success_conditions, failure_conditions,
      current_status: "进行中"
    }
  },

  ui: {                                // 任务面板 UI 数据
    narration: "...",
    phase_label: "任务进行中",
    rule_summary: "当前处于任务执行状态。直接输入你的行动推进任务；输入 #退出 视为放弃当前任务。",
    accepts_text_input: true,
    input_hint: "...",
    state_items: [
      { key: "任务标题", value: "..." },
      { key: "当前目标", value: "..." },
      ...
    ]
  }
}
```

#### `state.vars.activeFreeTask`（任务运行态）

```typescript
{
  title, category, description, objective,
  process, successConditions, failureConditions,
  status: "doing" | "completed" | "failed" | "aborted",
  eventIndex,
  reward?: { ... },                    // 完成时的奖励
  resolvedBy?: "...",                  // 触发结算的用户输入
  updateTime
}
```

## 5. 与小游戏标准链路的衔接

### 5.1 标准链路（与 `任务系统设计.md` L179-180 一致）

```
/game/orchestration/minigame  →  /game/streamlines  →  /game/streamvoice
        ↓                              ↓                       ↓
    编排师 plan                    生成旁白/NPC 台词           语音生成 + 播放
        ↓                              ↓                       ↓
    role / roleType /              台词写入 t_sessionMessage   音频流
    motive / eventType
```

### 5.2 各阶段对应的链路调用

| 阶段 | 链路调用 | 备注 |
|------|---------|------|
| 阶段 A 进入任务 | 仅 `/game/addMessage` 拦截 | handleMiniGameTurn 命中 create_task → 直接返回 `on_mini_game_start` 消息，**不走编排** |
| 阶段 B 任务开场 | minigame → streamlines → streamvoice | 旁白介绍任务目标 |
| 阶段 C 用户行动 | addMessage → minigame → streamlines → streamvoice | 用户每次输入都走完整链路 |
| 阶段 D1 任务成功 | maybeResolveActiveFreeChapterTaskEvent 命中 → `on_task_resolution` | 短路，**不走编排**，由结算文案直接落库 |
| 阶段 D2 任务失败 | 同 D1 | 区别在 `decision = failed` |
| 阶段 D3 用户退出 | `#退出` 命中 isForceQuitMiniGameCommand → `on_mini_game_abort` | addMessage 阶段直接拦截，**不走编排** |

## 6. 关键技术点

### 6.1 task 与其他小游戏的状态机差异

普通小游戏在 `MiniGameController.applyAction` 内推进状态机；
**task 由 AI 判定**（`maybeResolveActiveFreeChapterTaskEvent`）和**编排师**（`runNarrativeOrchestrator`）共同推动。

### 6.2 任务激活时跳过 AI 意图分析

为避免用户在任务中正常发言（如"先去操场"）被误判为新意图，`handleMiniGameTurn` 的 AI 意图分类**仅在无活跃任务时触发**：

```typescript
if (!hasActiveGame && !hasActiveTask) {
  // 跑 AI 意图分析（slow path）
} else {
  // 跳过，由小游戏内部消化用户输入
}
```

### 6.3 并发任务

用户已在任务中再创建新任务时：
- **不替换** `executing_task` / `activeTaskId`（仍指向原任务）
- 新任务**追加到 taskList**（status="doing"）
- 通过 `#切换任务 <id>`（T4.x 待实现）切换 active

### 6.4 任务结算优先级

```
maybeResolveActiveFreeChapterTaskEvent 优先级：
  1. AI 判定（evaluateFreeTaskResolutionByAi）
     └─ decision = "success" / "failed" → 直接采纳
  2. 规则判定（evaluateFreeTaskResolutionByRules）
     └─ AI 返回 "continue" 时兜底，关键词匹配触发 success/failed
  3. 静态条件（TaskProgressEngine.runTaskProgressEngine）
     └─ 评估 successCondition / failCondition
```

## 8. 完整对话流程示例（参考 `debug-mini-game.md` 模板）

> **关键**：任务模式不是纯旁白独白，而是**动态角色编排**。每轮编排师根据当前剧情上下文决定本轮由哪个角色发言（旁白/NPC/陪练/敌方），就像主线剧情一样，但目标是推进任务而非主章节。

```
  - 回合类型：NPC 发言回合
  - 编排：王思远（NPC 获救情绪）

- 【旁白】 当三位舍友都被带回宿舍，门一关上的瞬间，
  你听到走廊外传来阵阵叹息——任务【寻找失联舍友】已完成。
  - 事件: on_task_resolution / on_mini_game_finish
  - 回合类型：任务完成回合
  - 编排：旁白（任务结算文案）
```

### 8.2 动态角色编排机制（关键）

任务模式与普通小游戏（如挖矿/钓鱼）的最大差异是**角色编排不固定**：

| 编排维度 | 普通小游戏 | 任务模式 |
|---------|----------|---------|
| 发言角色 | 固定（仅旁白 + 陪练） | **由编排师每轮动态决定** |
| 角色范围 | rulebook 限定（如挖矿陪练） | **任意 NPC**（章节内已存在的角色） |
| 多 NPC 互动 | 不支持 | **支持**（一轮内可有多个 NPC 对话） |
| 编排依据 | 阶段状态机 | **当前剧情上下文 + 任务推进需要** |

**编排器决策逻辑**：

```
编排师 (NarrativeOrchestrator) 输入：
  - 章节信息 + 角色列表
  - 当前任务（executing_task）+ 任务进度
  - 最近 N 条对话
  - 用户最新输入

输出（每轮一个 plan）：
  - role: 本轮发言角色名（旁白 / 李明 / 小七 / 裂口女 / ...）
  - roleType: narrator / npc / player
  - motive: 本轮发言动机（"提供线索" / "应激反应" / "推进剧情" / ...）
  - eventType: on_orchestrated_reply
```

**单轮可有多个发言**（伪并行编排）：例如用户进入女厕所场景，本轮编排可能同时编排：
- 旁白：环境描写
- 裂口女：诡异提问
- 小七：介入化解

由 streamlines 串行生成台词，依次落库与播放。

### 8.3 NPC 关系推进示例

任务过程中 NPC 与用户建立的关系也会写入参数卡（任务结算后）：

```typescript
// 任务完成后角色卡更新（记忆 agent）
state.player.parameterCardJson:
  其他: [
    "李明的舍友（已救出）",
    "王思远的舍友（已救出，结识更深）",
    "赵小胖的舍友（已救出）",
    "小七：主动协助过救援，对其规则掌握度有疑问"   ← 伏笔记忆
  ]

state.npcs.李明.parameterCardJson:
  其他: [
    "信任许飞（救命之恩）",
    "知道许飞掌握诡异规则"
  ]
```

## 9. 任务退出流程

### 9.1 任务完成（success）

**触发条件**：
- AI 判定 `decision = "success"`（满足成功条件）
- 或规则匹配交付/汇报关键词

**结算步骤**：

```
1. 写入任务结果
   ├─ vars.activeFreeTask.status = "completed"
   ├─ vars.activeFreeTask.reward = { exp, items, money, ... }
   └─ vars.activeFreeTask.resolvedBy = "用户最后一句输入"

2. 发放奖励（reward agent）
   ├─ 经验值：state.player.parameterCardJson.exp += 任务奖励 exp
   │   └─ 升级判定：若 exp >= next_level_exp，触发 level + 1 + 满血满蓝
   ├─ 物品：state.player.parameterCardJson.items.push(...)
   ├─ 金钱：state.player.parameterCardJson.money += 任务奖励 money
   └─ 装备：state.player.parameterCardJson.equipment.push(...)

3. 角色关系变化（memory agent）
   ├─ 用户参数卡 other 字段追加："{NPC 名}的{关系}"（如"李明的舍友"）
   ├─ NPC 参数卡 other 字段追加：对用户态度变化（如"信任许飞"）
   └─ 更新 memory.summary / facts，沉淀任务成果

4. 清理任务态
   ├─ updateTaskListEntryStatus(taskId, "completed")
   │   └─ 删除 card.activeTaskId
   ├─ setExecutingTaskCardValue(state, null)   ← 参数卡"正在执行的任务"清空
   ├─ clearFreeTaskMiniGameState(state)         ← miniGame 面板消失
   └─ enterFreeChapterWaitingState(state)       ← 切回自由剧情等待
```

**回到主线（旁白总结回合）**：

任务完成后，**旁白主动输出一段任务总结**写入主线对话历史。这段总结同时是"主线干扰素材"——下一轮编排师会读到任务总结，可能影响后续主线走向。

```
- 【旁白】 任务【寻找失联舍友】已完成。三位舍友的失踪事件让你意识到，
  这所诡异校园远比表面看起来更危险——而表妹小七的反常表现，也越来越值得警惕。
  你回到走廊，主线剧情继续推进。
  - 事件: on_task_summary / on_orchestrated_reply
  - 回合类型：主线总结回合
  - 编排：旁白（任务回响 + 伏笔铺垫）
```

**主线干扰机制**：

| 总结内容 | 影响主线的方式 |
|---------|--------------|
| "三位舍友的失踪事件让你意识到..." | 后续编排师读取此总结，可能引出**新事件**（如教师调查、小七被怀疑） |
| "表妹小七的反常表现，越来越值得警惕" | **角色伏笔**写入记忆，后续小七出场时编排师可能调用此伏笔 |
| 奖励的特殊物品（如"老校徽"）| **道具触发器**，后续场景中校徽可能成为关键线索 |

### 9.2 任务失败（failed）

**触发条件**：
- AI 判定 `decision = "failed"`（命中失败条件）
- 或规则匹配撤退/逃跑/重伤等关键词

**结算步骤**：

```
1. 写入任务结果
   ├─ vars.activeFreeTask.status = "failed"
   └─ 不发放奖励

2. 角色状态可能受损（记忆 agent）
   ├─ 用户参数卡 other 追加：失败影响（如"在裂口女面前失态，导致李明对其失去信任"）
   └─ NPC 关系恶化

3. 清理任务态（同 9.1 第 4 步）
```

**回到主线**：

```
- 【旁白】 任务【寻找失联舍友】失败。你逃出洗手间，但王思远已被裂口女带走，
  生死未卜。校园里似乎多了一个新的诡异——它带着王思远的影子。
  - 事件: on_task_summary / on_orchestrated_reply
  - 回合类型：主线总结回合
  - 编排：旁白（失败后果 + 新威胁伏笔）
```

### 9.3 用户主动退出（#退出）

**触发条件**：用户输入 `#退出` / `#exit`（必须带 `#` 前缀）

**结算步骤**（与 9.2 失败几乎一致，区别仅在于结算文案）：

```
1. 调用 isForceQuitMiniGameCommand 检测命中
2. 调用 abandonActiveFreeChapterTaskEvent(state)
   ├─ updateTaskListEntryStatus(taskId, "aborted")
   ├─ setExecutingTaskCardValue(state, null)
   ├─ clearFreeTaskMiniGameState(state)
   └─ enterFreeChapterWaitingState(state)
3. suppressPassiveMiniGameReentry(root)
   └─ 禁止被动重新进入此任务
4. 返回 message.eventType = "on_mini_game_abort"
```

**回到主线**：

```
- 【旁白】 你主动放弃了【寻找失联舍友】任务。三位舍友的命运被你抛在身后——
  你或许会在某个深夜的梦里再次听到他们的呼救。
  - 事件: on_mini_game_abort / on_orchestrated_reply
  - 回合类型：主线总结回合
  - 编排：旁白（放弃后果 + 心理负担伏笔）
```

### 9.4 三种退出对比

| 退出方式 | taskList 状态 | 奖励 | 角色关系 | 主线总结基调 |
|---------|------------|------|---------|------------|
| **完成 (success)** | completed | ✅ 发放 | 正向（结识/感激） | 成就感 + 新伏笔 |
| **失败 (failed)** | failed | ❌ 无 | 负向（不信任/失态） | 后果 + 新威胁 |
| **放弃 (#退出)** | aborted | ❌ 无 | 中性（关系停滞） | 心理负担 + 遗憾 |
