## 核心设计思路

这个功能**不是一个独立的 UI 组件**，而是对现有"小游戏(MiniGame)"系统的复用：

```
后端返回 gameType === "task" 的 miniGame 数据
        ↓
复用小游戏面板展示 → 显示"任务面板"
        ↓
同时参数卡里会显示"正在执行的任务"
```

## 整体架构

这个功能**不是一个独立的 UI 组件**，而是复用现有"小游戏(MiniGame)"系统的设计：

```
用户说 "给我推荐个任务"
        ↓
后端 AI 旁白列出 5 个任务选项
        ↓
用户选择序号/任务名
        ↓
FreeChapterTaskService 解析选项 → 生成任务蓝图
        ↓
写入 state.miniGame = {
  rulebook.gameType = "task",    ← 触发小游戏面板
  session.game_type = "task",    ← 底部任务面板
  ui.state_items: [任务标题/目标/成功条件...] ← 面板详情
}
        ↓
同时写入 player.parameterCardJson.executing_task ← 参数卡显示
```

| 显示位置 | 触发条件 | 代码 |
|---|---|---|
| **参数卡 - "正在执行的任务"** | 后端在 `parameterCardJson.executing_task` 返回数据 | `ScenePlay.vue` |
| **底部 - 任务面板** | 后端返回 `miniGame.session.game_type === "task"` | `ScenePlay.vue`  |

## 任务完成判断 & 主动退出流程

### 一、任务完成的三条判断路径

#### 路径 A — AI 判定（主要方式）

`FreeChapterTaskService.ts` 的 `evaluateFreeTaskResolutionByAi()` 函数，将以下内容发送给 story 模型：

- 世界名、章节标题、任务详情（标题/目标/过程/成功失败条件）
- 玩家参数卡、最近 8 条对话历史
- 当前用户动作

模型返回 `{ decision, narration, reward }`，其中 `decision` 可选：
- `success` — 明确满足成功条件
- `failed` — 明确命中失败条件或明显撤退/放弃/重伤败退
- `continue` — 只是过程推进，不足以完成任务

#### 路径 B — 规则兜底判定

`evaluateFreeTaskResolutionByRules()` 函数，关键词匹配：

**触发失败（自动放弃）：**
```
#退出 / 放弃 / 撤退 / 逃跑 / 逃离 / 认输 / 中断任务 / 任务失败 / 被击退 / 重伤撤回
```

**触发成功（击杀头目）：**
- 命中 boss 关键词 + 包含 kill 关键词
- 命中交付关键词 + 目标包含交付/汇报/验收

#### 路径 C — 静态任务条件评估（可选）

`TaskProgressEngine.ts` 的 `runTaskProgressEngine()`，通过 `evaluateCondition()` 评估 `successCondition` / `failCondition`。

---

### 二、优先级与集成

`maybeResolveActiveFreeChapterTask()` 将三条路径组合：

1. **AI 优先**：AI 有明确 `success`/`failed` 结论时直接用
2. **规则兜底**：AI 返回 `continue` 时，用规则兜底判定

任务结果写入 `vars.activeFreeTask`：
```typescript
{
  status: decision === "success" ? "completed" : "failed",  // 或 "aborted"
  reward: resultReward.reward,
  resolvedBy: playerMessage,
  updateTime: nowTs(),
}
```

---

### 三、用户主动退出流程（`#退出`）

#### 触发条件

用户必须在输入框输入 **`#退出`** 或 **`#exit`**（带 `#` 前缀），普通文字"退出"不触发。

#### 后端处理链（`handleMiniGameTurn`）

```
用户输入 "#退出"
  → isForceQuitMiniGameCommand() 检测通过
  → 记录 session.status = "aborted", result = "aborted"
  → abandonActiveFreeChapterTaskEvent(state) 清理任务状态
    ├─ 写入任务记忆: status = "aborted"
    ├─ 清除参数卡中的任务: setExecutingTaskCardValue(null)
    ├─ 清空 miniGame state: clearFreeTaskMiniGameState()
    └─ 切回自由剧情等待: enterFreeChapterWaitingState()
  → suppressPassiveMiniGameReentry() 禁止被动重进
  → 返回 message.taskType = "on_mini_game_abort"
```

#### 前端响应

`ScenePlay.vue` 检测到 `taskType === "on_mini_game_abort"` 后：
- miniGame panel 消失（`activeMiniGame` 计算属性返回 null）
- 参数卡中的"正在执行的任务"被清空
- 可以继续主线剧情

---

### 四、task rulebook 配置

`MiniGameController.ts` 中 `task` rulebook 的关键设计：

```typescript
ruleSummary: "当前处于任务执行状态。直接输入你的行动推进任务；输入 #退出 视为放弃当前任务。"

applyAction: () => ({ narration: "当前任务需要通过直接输入行动来推进。" })
  // 透传，不拦截输入，让任务推进走主线编排
  // 只有 #退出 才会真正拦截
```

``` 
{
        code: "story-mini-game-task",
        name: "AI故事-小游戏-任务编排师",
        type: "subAgent",
        parentCode: "story-main",
        defaultValue:
          `AI故事-小游戏-任务编排师。
只做一件事：决定本轮由谁发言，以及剧情推进一小步。
## 要求：
- 不写台词、不写剧情正文
- 不复述章节或背景
- 每轮只推进一小步
- 返回结果要快速
- 偏向于角色说话直接推动剧情而不是旁白

## 输入参数说明：
### 已生成台词:
  - recent_dialogue 数组 按前后顺序记录了角色说了什么台词
  - 如果最后一句是问用户事情如"还请你告知姓名、性别与年龄" 那么就应该轮到用户发言
  - 如果最后一句是用户发言，那么就应该安排其他角色发言
  - 如果用户说了@角色名 就应该编排这个角色说话。

###`current_task` 表示本轮要推进的事件。

- `status`：事件状态  
  - `active`：正在推进
  - `waiting_input`：等待用户输入
  - `completed`：事件已完成

- `summary`：当前事件摘要，也是本轮主要依据  
  - 若格式为 `@角色名：xxx`，表示本轮应由该角色发言
  - 例如 `@旁白：xxx` → `speaker` 必须是 `旁白`
  - 例如 `@萧炎：xxx` → `speaker` 必须是 `萧炎`
  - `@角色名` 的优先级高于其他判断

- `facts`：当前事件关键信息  
  - 若为空，可根据 `summary` 补 1~2 条事实
  - 只写事实，不写剧情正文

- `memory_summary` / `memory_facts`：当前事件相关记忆信息

规则：

- `summary` 中有 `@角色名：xxx` 时，不要更换发言人
- `speaker` 必须等于 `@角色名`
- `role_type` 必须匹配该角色在角色列表中的类型
- `summary` 为空时，必须补 `task_summary` 和 `task_facts`

---

### turn_state：本轮发言状态

`turn_state` 表示系统对本轮发言的预期。

- `can_player_speak`：用户当前是否可以发言  
  - `true`：可以安排用户发言
  - `false`：不要安排用户发言

- `expected_role_type`：预期发言角色类型  
  - 如 `narrator` / `npc` / `player`

- `expected_role`：预期发言角色  
  - 如 `旁白`

- `last_speaker_role_type`：上一轮发言角色类型
- `last_speaker`：上一轮发言角色

规则：

- 若 `can_player_speak = false`：
  - 不要安排 `用户`
  - `role_type` 不要输出 `player`
  - `await_user` 通常为 `false`

- 若 `expected_role` 存在，可优先参考
- 若 `current_task.summary` 有 `@角色名：xxx`，则以 `@角色名` 为最高优先级
- `last_speaker` 只表示上一轮是谁，不代表本轮必须换人

## 规则：
1. speaker 必须来自当前角色列表，并符合 allowed_speakers
2. 若用户未发言，先安排一轮非用户推进
3. motive 用一句短话（10~25字）说明本轮要做什么
4. 不输出解释或多余内容
5. 编排用户要返回"role":"用户" 而不是用户的具体名称
6。"@旁白：xxx "。就是代表编排的角色是旁白的意思。"@角色名：xxx "。就是代表编排的该角色说话的意思

## 事件：
- 若 task_summary 为空 → 必须补一句 summary + 1~2条 facts
- summary：事件摘要，如果是@角色名：xxx, 那么就代表这个角色要说这句话
- facts：只保留关键信息


## 状态：
- task_adjust_mode: keep / update / waiting_input / completed
- task_status: active / waiting_input / completed

## 记忆：
- 有新信息或变化 → trigger_memory_agent=true
- 否则 false
- 用户信息发生变化，等级，物品，技能 等→ trigger_memory_agent=true
- 用户输入了"@记忆管理 xxx"  → trigger_memory_agent=true
- 旁白输入了"@记忆管理 xxx"  → trigger_memory_agent=true

## 输出（逐行）：
role_type:
speaker:
motive:
await_user:
trigger_memory_agent:
task_adjust_mode:
task_status:
task_summary:
task_facts:`,
      }
```

# AI故事-小游戏-任务编排-Agent 设计方案

## 一、设计目标

任务系统是复用现有"小游戏(MiniGame)"系统的支线剧情，需要一套完整的 AI Agent 编排体系来管理：

1. **谁说话** — 发言人和角色类型编排
2. **说话动机** — 本轮发言目的和动机（motive）
3. **进度控制** — 任务阶段推进和状态变化
4. **完成判断** — 任务成功/失败的三层判定机制
5. **退出处理** — #退出 命令的拦截和状态清理
6. **动态修改** — 任务状态、目标、条件的运行时修改

---

## 二、Agent 架构：多 Agent 协作

任务编排不采用单一 Agent，而是拆分为 **3 个专注的子 Agent**：

```
┌─────────────────────────────────────────────────────────┐
│                  任务编排总控 (TaskOrchestrator)           │
│                  负责协调各子 Agent 工作                   │
└────────────────┬──────────────────────┬─────────────────┘
                 │                      │                      │
                 ▼                      ▼                      ▼
┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐
│  TaskIntentAgent    │  │ TaskProgressAgent     │  │ TaskSpeakerAgent   │
│  任务意图分析        │  │  任务进度评估       │  │  任务发言编排       │
│  判断用户意图        │  │  判定完成/失败      │  │  决定谁说话/动机    │
│  create/exit/query  │  │  三层判定机制       │  │  推进剧情          │
└────────────────────┘  └────────────────────┘  └────────────────────┘
```

---

## 三、各子 Agent 详细设计

### 3.1 TaskIntentAgent（任务意图分析）

**职责**：分析用户输入，判断任务相关意图

**输入**：
```typescript
{
  userMessage: string,           // 用户原始输入
  recentMessages: Message[],     // 最近对话历史
  activeTask: Task | null,       // 当前任务（如果有）
  miniGameState: MiniGame,       // 当前小游戏状态
  chapterContext: ChapterContext  // 章节上下文
}
```

**输出**：
```typescript
{
  intent: "create_task" | "exit_task" | "query_taskProgress" | "game_action" | "normal_dialog",
  confidence: number,            // 0-1
  reasoning: string,             // 分析理由
  extractedParams?: {
    taskName?: string,
    taskGoal?: string,
    exitReason?: string
  }
}
```

**判断规则**：

| 意图 | 触发条件 | 优先级 |
|------|----------|--------|
| `exit_task` | 用户输入 `#退出` 或 `#exit` | 1（最高） |
| `query_taskProgress` | 包含"进度/状态/完成多少"等关键词 | 2 |
| `create_task` | 包含"任务/接任务/给我任务"等 | 3 |
| `game_action` | 数字选项（1/2/3）或明确动作词 | 4 |
| `normal_dialog` | 其他所有输入 | 5（兜底） |

**提示词模板**：

```
你是任务意图分析专家。根据用户输入和当前上下文，判断用户的真实意图。

当前上下文：
- 当前任务：{activeTaskTitle}
- 任务状态：{activeTaskStatus}
- 最近对话：{recentMessages}

用户输入：{userMessage}

请分析用户意图：
- 如果用户输入 #退出 或 #exit → 意图 = "exit_task"
- 如果用户询问任务进度/状态/完成情况 → 意图 = "query_taskProgress"
- 如果用户要求接任务/创建任务 → 意图 = "create_task"
- 如果用户选择数字选项或执行动作 → 意图 = "game_action"
- 其他 → 意图 = "normal_dialog"

输出 JSON：
{
  "intent": "意图类型",
  "confidence": 0.0-1.0,
  "reasoning": "分析理由"
}
```

---

### 3.2 TaskProgressAgent（任务进度评估）

**职责**：判断任务是否完成、失败或需要继续推进

**输入**：
```typescript
{
  taskBlueprint: FreeChapterTaskBlueprint,  // 任务蓝图
  taskStatus: "doing" | "paused",
  userMessage: string,           // 用户当前动作
  recentDialogue: Message[],    // 最近对话
  playerCard: PlayerCard,       // 玩家参数卡
  processSteps: string[],       // 任务过程阶段
  successConditions: string[],   // 成功条件
  failureConditions: string[]   // 失败条件
}
```

**输出**：
```typescript
{
  decision: "success" | "failed" | "continue",
  narration: string,            // 收尾旁白
  reward?: {
    exp: number,
    money: number,
    items: string[]
  },
  taskProgressUpdate?: {
    currentStep: number,
    nextObjective: string,
    taskFacts: string[]
  }
}
```

**三层判定机制（优先级从高到低）**：

#### 层级 1 — 静态条件判定（最快）

检查 `successCondition` / `failCondition` 中的 JSON 表达式条件：

```
if (evaluateCondition(failCondition, { state, messageContent })) → "failed"
if (evaluateCondition(successCondition, { state, messageContent })) → "success"
```

#### 层级 2 — 规则兜底判定（关键词匹配）

当层级 1 无法判定时，使用关键词匹配：

**失败触发词**：
```
放弃、撤退、逃跑、逃离、认输、中断任务、任务失败、被击退、重伤撤回
```

**成功触发词**（需同时满足）：
- 成功条件关键词 + 交付/汇报/验收 关键词
- 头目关键词 + 击杀/击败关键词

#### 层级 3 — AI 智能判定（最准确）

当层级 1 和 2 都返回 `continue` 时，调用 AI 模型判断：

```
系统提示：
你是任务完成判定专家。根据用户动作和任务条件，判断任务是否完成。

任务信息：
- 标题：{taskTitle}
- 目标：{objective}
- 成功条件：{successConditions}
- 失败条件：{failureConditions}
- 过程阶段：{processSteps}

用户动作：{userMessage}

请判断：
- 用户明确完成成功条件中的要求 → decision = "success"
- 用户明确触发失败条件 → decision = "failed"
- 只是推进过程，未完成 → decision = "continue"

输出 JSON：
{
  "decision": "success|failed|continue",
  "reasoning": "判断理由",
  "narration": "收尾旁白（如果是 success/failed）",
  "reward": { "exp": number, "money": number, "items": [] }
}
```

### 3.3 TaskSpeakerAgent（任务发言编排）

**职责**：决定本轮由谁发言、发言动机、事件状态

**输入**：
```typescript
{
  recentDialogue: Message[],     // 最近对话（role/speaker/content）
  currentTask: {
    summary: string,            // 事件摘要（可能含 @角色名：xxx）
    facts: string[],            // 事件事实
    status: "active" | "waiting_input" | "completed"
  },
  turnState: {
    canPlayerSpeak: boolean,    // 用户是否可以发言
    expectedRole?: string,      // 预期角色
    lastSpeaker: string,       // 上一轮发言人
    lastSpeakerRoleType: string
  },
  taskContext: {
    taskTitle: string,
    currentObjective: string,
    processSteps: string[],
    allowedRoles: string[]     // 可选角色列表
  },
  memorySummary: string,       // 记忆摘要
  memoryFacts: string[]        // 记忆事实
```

   - 用户选择明确选项 → `taskAdjustMode = "update"`

   - 任务结束 → `taskAdjustMode = "completed"`

### 4.1 入口流程

```
                                    ↓

                          │                 │

                  handleTaskEnd()    TaskSpeakerAgent.orchestrate()

                                            │
                                            ▼
                                    返回给前端 + 更新状态
```

### 4.2 核心调度代码（伪代码）

```typescript
async function orchestrateTaskTurn(input: TaskOrchestratorInput): Promise<TaskOrchestratorResult> {
  const { userMessage, recentMessages, miniGameState, state } = input;

  // Step 1: 意图分析
  const intentResult = await TaskIntentAgent.analyze({
    userMessage,
    recentMessages,
    activeTask: readActiveFreeTaskState(state),
    miniGameState
  });

  // Step 2: 分流处理
  switch (intentResult.intent) {
    case 'exit_task':
      return await handleExitTask(state, intentResult);

    case 'query_taskProgress':
      return await handleQueryTaskProgress(state, intentResult);

    case 'game_action':
    case 'normal_dialog':
    default:
      return await handleTaskProgress(state, input, intentResult);
  }
}

async function handleTaskProgress(
  state: JsonRecord,
  input: TaskOrchestratorInput,
  intentResult: IntentResult
): Promise<TaskOrchestratorResult> {
  // Step 1: 进度评估
  const taskProgressResult = await TaskProgressAgent.evaluate({
    taskBlueprint: readTaskBlueprint(state),
    userMessage: input.userMessage,
    recentDialogue: input.recentMessages,
    playerCard: state.player.parameterCardJson,
    processSteps: readProcessSteps(state),
    successConditions: readSuccessConditions(state),
    failureConditions: readFailureConditions(state)
  });

  // Step 2: 任务结束处理
  if (taskProgressResult.decision !== 'continue') {
    return await handleTaskEnd(state, taskProgressResult);
  }

  // Step 3: 发言编排
  const speakerResult = await TaskSpeakerAgent.orchestrate({
    recentDialogue: input.recentMessages,
    currentTask: readcurrentTask(state),
    turnState: buildTurnState(input),
    taskContext: buildTaskContext(state),
    memorySummary: state.memorySummary,
    memoryFacts: state.memoryFacts
  });

  // Step 4: 更新状态
  await updateTaskState(state, speakerResult, taskProgressResult);

  // Step 5: 返回编排结果
  return buildNarrativePlan(speakerResult);
}
```

| NPC刚发言 | 2 | 用户 | player | "等待用户决策" |

| 任务失败 | 1 | 旁白 | narrator | "描述失败原因" |

### 8.2 动机生成规则

**任务开始阶段**：
- 动机词库：`宣布任务开始`、`说明任务目标`、`引导首个步骤`
- 生成逻辑：`当前过程阶段[0]`

**推进阶段**：
- 动机词库：`推进任务进展`、`描述当前状态`、`引导下一步行动`
- 生成逻辑：`任务目标 + 用户动作的关联`

**遇到困难**：
- 动机词库：`描述困境`、`提供可选方案`、`给予安慰鼓励`
- 生成逻辑：`当前困难点 + 可能解决方向`

**任务收尾**：
- 动机词库：`宣布任务完成`、`说明奖励内容`、`总结任务收获`
- 生成逻辑：`decision 结果 + reward 内容`

## 十六、任务-角色发言器 Agent 设计（/game/streamlines 任务模式）

> 本章节设计 `/game/streamlines` 在 `game_type=task` 时的行为模式。
> 前置链路：`/game/orchestration/minigame` → streamlines → streamvoice。
> 本章节与第 4 章（编排层）、第 9 章（发言选择矩阵）配套。

### 16.1 角色定位

`/game/streamlines` 是任务系统的**台词生成引擎**，不是独立 Agent。它接收编排层（TaskOrchestrator）发来的 `plan`：

```typescript
plan: {
  role: string;           // 谁说话（来自编排层决策）
  roleType: string;        // narrator | npc | enemy
  motive: string;          // 说话动机（来自编排层）
  taskType: string;       // on_mini_game_* 系列
  presetContent?: string;  // 规则说明时直接使用
}
```

它做的事：**把 role + motive + taskContext 翻译成最终展示给用户的台词**，不决策谁说话、不判断任务进度。

### 16.2 taskType 路由表

| taskType | 含义 | 台词特征 | 备注 |
|-----------|------|----------|------|
| `on_mini_game_start` | 任务开场（规则说明） | 直接用 `presetContent`（跳过 AI） | 字数限制会破坏规则完整性 |
| `on_mini_game` | 用户输入后，旁白/NPC 回应 | 40~120 字，承接用户行为 + 推进任务 | 最常见类型 |
| `on_mini_game_status` | 任务状态播报 | 简洁客观，说明当前状态 | 可复用 `on_mini_game` |
| `on_mini_game_rule` | 规则分支说明 | 直接用 `presetContent` | 同 `on_mini_game_start` |
| `on_mini_game_progress` | 任务阶段推进旁白 | 环境/氛围描写 + 下一步提示 | 可复用 `on_mini_game` |
| `on_mini_game_complete` | 任务完成播报 | 总结 + 奖励说明 | 旁白专属 |
| `on_mini_game_failed` | 任务失败播报 | 说明失败原因 + 后续建议 | 旁白专属 |

**现有代码实现**：`NarrativeOrchestrator.ts:3961` 的 `isMiniGameMode` 判断。

### 16.3 任务上下文注入机制

已实现的注入链路（无需新增代码）：

```
state.miniGame.public_state
  ↓ extractTaskContext(state)
  ↓ buildTaskContextLines(task)
  ↓ buildSpeakerSystemPrompt(..., taskContext)
  → 注入到 system prompt 末尾的 taskModeExtra
  → 注入到 user prompt 的 [当前任务模式] 区块
```

**system prompt 约束**（`NarrativeOrchestrator.ts:3380`）：

1. 只能在旁白 / 章节内 NPC / 敌方诡异 中选一个发言
2. 本轮台词必须**直接服务于任务推进**：提供线索 / 制造冲突 / 推进用户行动
3. 绝不允许推进章节主线剧情或开启新事件
4. 不要复述章节开头、世界观、章节内其他事件的背景
5. 必须给用户留下可继续的输入切入点

### 16.4 与编排层（TaskOrchestrator）的分工

| 决策项 | 由谁决定 | 通过什么 |
|--------|----------|----------|
| 谁说话（role） | TaskSpeakerAgent（编排层） | plan.role 传递给 streamlines |
| 说话动机（motive） | TaskSpeakerAgent（编排层） | plan.motive 传递给 streamlines |
| 事件类型（taskType） | TaskSpeakerAgent（编排层） | plan.taskType 传递给 streamlines |
| 具体台词内容 | streamlines（发言器层） | runStorySpeakerContent() |
| 台词风格 | streamlines（发言器层） | speaker prompt + taskContext |
| 任务进度判断 | TaskProgressAgent（编排层） | orchestration 层独立判断 |

### 16.5 与主线 taskSummary/taskFacts 的隔离
