# 小游戏设计

## 1. 概述

小游戏是 AI 故事游戏中用于调节对话节奏、增加互动深度的玩法模块。通过小游戏可以：
- 丰富游戏体验
- 提供资源获取途径
- 增强角色关系互动
- 制造剧情转折

## 2. 小游戏列表

| 类型 | 描述 | 触发方式 |
|------|------|---------|
| `battle` | 战斗系统 | `#战斗 角色名` |
| `fishing` | 钓鱼系统 | `#钓鱼` |
| `mining` | 挖矿系统 | `#挖矿` |
| `alchemy` | 炼药系统 | `#炼药` |
| `cultivation` | 修炼系统 | `#修炼` |
| `research_skill` | 研发技能 | `#研发技能` |
| `upgrade_equipment` | 升级装备 | `#升级装备` |
| `werewolf` | 狼人杀 | `#狼人杀` |

## 3. 触发机制

### 3.1 主动触发

用户输入标签直接进入：
```
#狼人杀 #钓鱼 #修炼 #研发技能 #炼药 #挖矿 #升级装备 #战斗
```

### 3.2 被动触发

剧情中自然触发，例如：
- 烧烤局有人提议狼人杀
- 路遇野怪触发战斗
- 遇到炼药师邀请炼药

## 5. 公开态与隐藏态

### 5.1 分离原则

- `public_state`：用户可感知的信息
- `hidden_state`：只给控制器和后端看

### 5.2 推荐约束

1. 身份类秘密放 `hidden_state`
2. NPC 决策倾向放 `hidden_state`
3. 预生成随机序列放 `rng_state`
4. 用户可感知到的资源放 `public_state`
5. 奖励预览只显示范围，不显示隐藏结果

## 6. 随机数机制

### 6.1 RNG 设计

后端预先给一个 `rng_queue`：
- 每次需要随机判定时，控制器只消费队首或按 `cursor` 取值
- 所有公式都写在规则卡中，结果可复算
- `action_log` 记录本次用了哪个随机值

### 6.2 目的

防止模型每轮胡乱"看感觉"判定，保证结果可复现。

## 7. 通用流程

### 7.1 进入流程

1. 判断触发来源：主动输入标签或主线事件触发
2. 检查进入条件：场景、角色、道具、体力、时间段
3. 创建 `mini_game_session`
4. 冻结主线快照摘要，记录本局可写回白名单
5. 控制器返回开场说明、当前状态和第一批可选动作

### 7.2 局内流程

每一轮固定顺序：
1. 读取当前 `phase` 和 `public_state`
2. 用户输入动作，系统做动作归一化
3. 控制器根据规则卡和随机数计算结果
4. 产出 `state_delta`
5. 应用 `delta` 后写入 session snapshot
6. 判断是否换阶段、换轮次或结算
7. 返回叙述文案、UI 状态和下一轮动作

### 7.3 结算流程

1. 进入 `settling`
2. 计算胜负、品质、产出、损耗、关系变化
3. 生成 `writeback_delta`
4. 只回写白名单字段
5. 写入一条 `mini_game_summary` 到中期记忆
6. 把 `status` 改为 `finished`

### 7.4 暂停、恢复、退出

局内指令：
1. `查看状态`
2. `查看规则`
3. `继续`
4. `申请退出`
5. `确认退出`
6. `恢复小游戏`

协议：
- `active` 状态下，若用户输入主线内容，控制器不进入主线
- `申请退出` 先进入确认，不直接丢局
- `suspended` 恢复后必须先返回局面摘要

## 8. 动作归一化

### 8.1 输入规范

两种输入方式：
1. **UI 按钮动作**：最稳定，直接传 `action_id`
2. **自然语言动作**：控制器映射到最近的合法动作

### 8.2 合法性校验

如果用户输入不合法：
1. 不推进轮次
2. 不改动局内状态
3. 明确告知当前合法动作列表

## 9. 主线回写白名单

小游戏结算后允许回写以下字段：

| 允许 | 不允许 |
|------|--------|
| `player_state.resources` | `current_chapter_id` |
| `player_state.inventory` | `current_scene_id` |
| `player_state.action_state` | 未触发的主线剧情信息 |
| `player_state.flags` | 新增未铺垫的重要世界设定 |
| `relationship_state` | 角色基础参数卡原始值 |
| `progress.side_quests` | |
| `event_pool.done` | |
| `event_pool.failed` | |
| `memory_state.mid_term` | |

## 10. 统一奖励规则

奖励由 3 层组成：

### 10.1 固定奖励

- 经验
- 少量货币
- 局内消耗返还

### 10.2 表现奖励

根据评分、品质、是否无伤、是否首局通关追加。

### 10.3 场景奖励

由当前章节或地点注入，例如：
- 烧烤局狼人杀后关系升温
- 灵脉挖矿额外掉灵石

### 10.4 评分等级

| 等级 | 说明 | 奖励 |
|------|------|------|
| S | 超额完成 | 稀有奖励 |
| A | 成功完成 | 标准奖励 |
| B | 勉强完成 | 基础奖励 |
| C | 失败或中断 | 安慰奖励或无奖励 |

## 11. 控制边界

### 11.1 控制器只允许处理

1. 小游戏内部的轮次与阶段
2. 局内身份、资源、行动与结算
3. 小游戏奖励与惩罚的结构化回写
4. 小游戏结果摘要写入主线记忆

### 11.2 控制器不允许处理

1. 改写主线剧情结构
2. 提前泄漏未解锁章节、角色秘密、后续事件
3. 越权生成新主线任务
4. 越权修改角色基础设定卡
5. 把小游戏中的隐藏态直接说给用户
