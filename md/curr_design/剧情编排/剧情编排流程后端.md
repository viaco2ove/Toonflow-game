# 剧情编排流程文档（后端）

## 概述

后端剧情编排是游戏运行时自动推进故事的核心机制。它负责：
1. 根据当前剧情状态和角色设定，决定下一句台词的角色和动机
2. 调用 LLM 生成符合角色和动机的台词
3. 管理回合状态（轮到谁发言）

## 关键文件

| 文件 | 职责 |
|------|------|
| `src/modules/game-runtime/services/SessionService.ts` | 编排核心服务，处理 `/game/orchestration` 请求 |
| `src/modules/game-runtime/services/StreamLinesService.ts` | 流式台词生成服务 |
| `src/modules/game-runtime/services/StoryInfoService.ts` | 故事状态信息服务 |
| `src/modules/game-runtime/prompt/orchestration_prompt.ts` | 编排 prompt 模板 |

## API 接口

### 1. POST /game/orchestration

**用途**：获取下一句台词的角色和动机

**请求参数**：
```json
{
  "sessionId": "会话 ID"
}
```

**响应**：
```json
{
  "code": 200,
  "data": {
    "role": "旁白",
    "roleType": "narrator",
    "motive": "推进抵达顾家宅邸的剧情节点"
  },
  "message": "成功"
}
```

**特殊返回**：
- 当轮到用户发言时，返回：
```json
{
  "role": "用户",
  "roleType": "player",
  "motive": "等待用户输入"
}
```

### 2. POST /game/streamlines

**用途**：流式生成台词

**请求参数**：
```json
{
  "sessionId": "会话 ID",
  "plan": {
    "role": "旁白",
    "roleType": "narrator",
    "motive": "推进抵达顾家宅邸的剧情节点"
  }
}
```

**响应**：SSE 流式输出，每条消息格式：
```json
{"type": "delta", "data": {"text": "（身穿制服的司机透过后视镜扫了你一眼）"}}
{"type": "done", "data": {"message": {...}}}
```

## 编排流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        POST /game/orchestration                              │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          evaluateEventProgressByAi                            │
│  评估当前事件进度（异步 AI 分析）                                             │
│  - 如果事件已完成，触发下一事件                                               │
│  - 如果章节已完成，触发下一章节                                               │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          evaluateChapterOutcomeByAi                          │
│  评估章节结果（异步 AI 分析）                                                 │
│  - 检测章节是否已完成                                                         │
│  - 如果完成，触发下一章节                                                     │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        编排 Prompt 生成                                       │
│  - 构建包含角色设定、剧情上下文、回合状态的 prompt                             │
│  - 使用 orchestrator prompt 模板                                             │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        调用 LLM 生成编排结果                                  │
│  - 返回 role, roleType, motive                                              │
│  - roleType: narrator(旁白) | npc(NPC) | player(用户)                       │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        更新回合状态                                           │
│  - 如果 roleType === "player"，设置 canPlayerSpeak = true                    │
│  - 否则设置 canPlayerSpeak = false                                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 关键逻辑

### 1. 回合状态 (turnState)

```typescript
interface TurnState {
  canPlayerSpeak: boolean;      // 是否轮到用户发言
  expectedRole: string;        // 预期发言角色
  expectedRoleType: string;    // 角色类型
  lastSpeakerRoleType: string; // 上一位发言者类型
}
```

### 2. 事件进度评估 (evaluateEventProgressByAi)

**触发时机**：每次 `/game/orchestration` 请求时

**逻辑**：
1. 获取当前事件上下文（eventDigest）
2. 调用 AI 分析当前事件是否完成
3. 如果完成，生成下一事件推进
4. 更新 session 状态

**注意**：不能跳过 "." 或短消息的事件进度判定

### 3. 章节结果评估 (evaluateChapterOutcomeByAi)

**触发时机**：每次 `/game/orchestration` 请求时

**逻辑**：
1. 检查当前章节是否有结束条件
2. 调用 AI 评估章节是否完成
3. 如果完成，生成下一章节

## 常见问题

### 1. 剧情卡住不推进

**可能原因**：
- 事件进度评估或章节结果评估卡住
- LLM 返回格式不正确
- 回合状态异常

**排查步骤**：
1. 检查服务端日志是否有 `evaluateEventProgressByAi` 或 `evaluateChapterOutcomeByAi` 错误
2. 检查 LLM 调用是否超时
3. 检查 `storyInfo.turnState.canPlayerSpeak` 是否正确

### 2. "." 消息跳过事件进度

**问题**：发送 "." 或短消息时，事件进度评估被跳过，导致剧情无法推进

**修复**：确保 "." 和短消息**不跳过** `evaluateEventProgressByAi` 和 `evaluateChapterOutcomeByAi`

## 与前端的协作

1. 前端调用 `/game/orchestration` 获取下一句台词的角色和动机
2. 如果返回 `roleType === "player"`，前端显示用户输入框，等待用户发言
3. 如果返回其他角色，前端调用 `/game/streamlines` 流式生成台词
4. 台词生成完成后，前端进入等待状态，直到消息揭示完成
5. 消息揭示完成后，前端再次调用 `/game/orchestration` 获取下一句
