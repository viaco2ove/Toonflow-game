### 整体判断

方案1 格式专业，但**直接照搬酒馆全套字段对当前项目过度设计，且有架构隐患**。建议方案2 大幅精简后再做，且时序上排在 P1 之后。

### 一、会打架的字段（危险）

- **`probability` 控时序 vs 章节状态机**：方案1 用 `probability:0` 控制"后期角色前期不登场"。但角色登场时机本应由章节状态机的 `phase` / `allowedSpeakers` 管。两套时序并存必冲突：章节推进了但概率还是 0（忘改）、或概率变 100 但章节没到。
- **`order` 分层 vs 结构化分区**：酒馆用 order 控注入位置，因为它只有一条扁平管道。本项目 `buildOrchestratorPromptPayload` 已是结构化分区（世界/章节/角色/事件/回合）。再叠 order 排序，语义混乱。
- **`group` 互斥**：25~30 条目规模，互斥场景极少，可用 `category` + 简单规则替代。

### 二、重复的字段（冗余，违反单一数据源）

| 世界书类目 | 已有等价物 | 冲突 |
|---|---|---|
| `characters` | NPC 参数卡 `parameterCardJson` | 同一 NPC 设定存两份，谁更新？编排师看哪个？ |
| `items` | 玩家/NPC 参数卡 `items` | 同上 |
| `factions` | `worldGlobalBackground` 势力设定 | 同上 |
| `constants` 总纲 | `worldGlobalBackground` | 重复 |

最尖锐：`characters` 条目 vs NPC 参数卡，直接违反 P0 方案确立的"单一数据源"原则。

### 三、方案2 保留的字段（精简到 5 个）

`title` / `category` / `keys` / `constant` / `content`。`probability` **仅 `random` 类目保留**，其余删除。砍掉 `selectiveLogic` / `selectiveKeys` / `group` / `order` 分层。`category` 只保留参数卡覆盖不了的：`locations` / `events` / `world` / `random`（角色/物品/势力用参数卡，不进世界书）。

### 四、注入引擎三个待回答问题

1. **扫描什么**：应扫描编排师 payload 的 `recentDialogue` + `latestPlayerMessage`，不是原始消息表，否则数据通路与编排师脱节。
2. **token 预算**：2000 token 默认值必须与 `compact`/`advanced` 模式联动，compact 模式要更小，否则 compact 不 compact。
3. **与 `worldBreathing` 的关系（最关键）**：P0 的 `worldBreathing`（动态状态：时间/天气/NPC 活动）和 `worldKnowledge`（静态设定）应**合并成 payload 同一个 `worldContext` 区块**，而非各搞一套，否则编排师面对两个世界信息源不知谁优先。

### 五、时序建议：现在不做，排在 P1 之后

- P0 的 `worldBreathing` 已是一个（简陋的）世界知识注入（从 `dynamicWorldGlobalBackground` + `memoryFacts` 提取）。先看 P0 + P1 上线后自由模式够不够鲜活，不够再上世界书。
- 世界书解决"上下文装不下所有设定"，但本项目 25~30 条目规模，`worldGlobalBackground` + 参数卡可能已够。世界书为超大世界准备，当前世界可能不够大。
- **数据来源比引擎本身更棘手**：25~30 条目谁写？手填工作量巨大，AI 生成质量不可控。引擎建好数据是空的 = 白搭。

### 六、分阶段建议

- **阶段 1（现在）**：只定精简格式（5 字段），不写引擎。
- **阶段 2（P1 落地后）**：若发现地点氛围/事件背景等静态知识确实缺，再做注入。`keys` 匹配 `recentDialogue` + `latestPlayerMessage`；与 `worldBreathing` 合并成 `worldContext`；token 预算联动 compact/advanced；`category` 只留 `locations`/`events`/`world`/`random`。
- **阶段 3（真有需要时）**：`random` 类目多到需互斥控制，再补 `group`/`probability`。
