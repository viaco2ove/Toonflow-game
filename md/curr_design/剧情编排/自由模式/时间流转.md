# web 的play-head__sub  后面增加
[timeOfDay/天气] [模式选择]

模式:轮转tick/剧情推动/现实同步/手动
模式值:tick/narrative/realtime/manual
默认为:剧情推动

时间天气流转模式数据要存到存档

## 轮转tick
正常:
  轮1: timeOfDay=清晨  (tick=0 或 1)
  轮2: timeOfDay=上午
  轮3: timeOfDay=正午
  ...
  轮8: timeOfDay=午夜
  轮9: timeOfDay=清晨  (tick%8 循环回来)
  轮10: timeOfDay=上午
  时间单调推进,到午夜后循环回清晨。weather 跟着时段变(清晨晴/下午多云/深夜阴)。

## 剧情推动模式

### 核心理念
时间不再每轮机械 +1,而是**跟着剧情走**:剧情明确发生时间流逝时才推进,没流逝就停在当前时段。
和 tick 模式的区别:tick 是"世界自己转",narrative 是"剧情拖着世界转"。

### 两层判定(按可靠性从高到低,命中即停)

**第 1 层:编排师显式声明(最可靠)**
编排师 JSON 返回里新增可选字段 `time_advance`:
```json
{
  "speaker": "旁白",
  "motive": "主角在客栈睡了一觉,天色大亮",
  "time_advance": { "slots": 2, "reason": "睡了一觉到第二天上午" }
}
```
- `slots`:推进的时段数(1=下一个时段, 8=一整天循环回来, 0=不推进)
- `reason`:为什么推进(仅 debug 用,不入存档)
- 字段缺失/为 0 = 本轮不推进时间
- 提示词里告诉编排师:**只有当本轮台词/旁白明确描述了时间流逝(过夜/赶路数日/修炼闭关)才填,日常对话不要填**

**第 2 层:关键词正则兜底(编排师没填 time_advance 时)**
保留 `detectNarrativeTimeJump`,扫 `motive` + `eventSummary`:
- 过夜/睡了一觉/次日/翌日/第二天 -> +1
- N天后/数日后/一周后 -> +8*N
- 扩充关键词:日上三竿/不知不觉天黑/月升/旭日东升/暮色四合 -> +1

### 不推进时
- worldClock.tick 不变,timeOfDay/weather 保持(narrative 模式时间可无限凝固,不设停滞保护)
- `world_breathing` 照常注入提示词(让编排师看到"现在还是清晨")
- 叙事钩子计数(`lastHookTick`)照常基于 tick,所以 narrative 模式下钩子间隔可能拉长(因为 tick 不动),这是预期行为

### 与 tick 模式的边界
| | tick | narrative |
|---|---|---|
| 每轮必推进 | 是 | 否(看剧情) |
| 推进量 | 固定 +1 | 0 / +1 / +N(剧情决定) |
| 卡住风险 | 无 | 时间可凝固(纯对话不推进,预期行为) |
| 适合场景 | 纯日常沙盒 | 有明确时间线的剧情 |

### 落库
和 tick 模式一样,推进后在 `finalizeOrchestrationResult` 落库前写回 `state.vars.worldClock`。
realtime 模式不落库,narrative/tick 都落库。

### debug 日志(narrative 模式专属)
```
[worldClock] narrative mode      { motivePreview, explicitSlots, detectedJump }
[worldClock] narrative advanced  { from, to, jump, source: "explicit"|"keyword" }
[worldClock] narrative no jump   { reason: "本轮无时间流逝" }
```
