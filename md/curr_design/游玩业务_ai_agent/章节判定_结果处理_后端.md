# 章节判定结果处理

## 1. 概述

章节判定（Chapter Outcome Judge）是判断章节是否应该结束的核心模块。每次用户发言后都会触发判定，决定章节是继续推进、成功结束、失败结束，还是需要引导用户完成条件。

## 2. 架构总览

```
用户发言
    │
    ▼
evaluateRuntimeOutcome()  ← 统一入口
    │
    ├─► buildRuleBasedChapterOutcome()     ← 规则引擎（快速路径）
    │       │
    │       ▼
    │   evaluateChapterOutcome()           ← ChapterOutcomeEngine
    │       ├── 检查 runtimeOutline.endingRules.success/failure
    │       ├── 检查 completionCondition（结构化）
    │       └── 返回 hasRule + result
    │
    ├─► isNaturalLanguageCompletionCondition()  ← 自然语言检测
    │
    └─► 门控决策
            │
            ├─ 条件为结构化规则 && 规则返回 continue → 跳过 AI
            └─ 条件为自然语言 || 规则返回 success/failed/guide → 调用 AI
                    │
                    ▼
            evaluateChapterOutcomeByAi()    ← AI 判定（慢速路径）
                │
                ├── 加载 story-chapter Prompt
                ├── 构建输入快照（buildChapterJudgeInputSnapshot）
                ├── 调用 AI 模型
                └── 返回 ChapterOutcomeResult
```

## 3. 核心概念

### 3.1 章节结局类型

| 结果 | 含义 |
|------|------|
| `continue` | 章节继续推进，未满足任何结束条件 |
| `guide` | 需要引导用户完成结束条件（下一事件不存在时触发） |
| `success` | 章节成功结束，条件已满足 |
| `failed` | 章节失败结束，条件已无法达成 |

### 3.2 章节结束条件来源

章节结束条件来自两个地方，优先级从高到低：

1. **`chapter.runtimeOutline.endingRules`** — 结构化规则，定义成功/失败的事件 ID 列表
2. **`chapter.completionCondition`** — 章节完成条件，支持两种格式：
   - **结构化 JSON**：如 `{ "success": { "type": "event", "field": "completedEvents", "op": "contains", "value": "event_1" } }`
   - **自然语言文本**：如 `"用户成功抢夺顾子航的房间"`

### 3.3 自然语言条件 vs 结构化规则

| 类型 | 示例 | 规则引擎 | AI 判定 |
|------|------|----------|---------|
| 结构化 JSON | `{ "success": { "type": "event", "field": "completedEvents", "op": "contains", "value": "event_1" } }` | ✅ 可解析 | 复核 |
| 自然语言文本 | `"用户成功抢夺顾子航的房间"` | ❌ 无法解析 | ✅ 必须调用 |
| 空/null | — | 跳过判定 | 跳过判定 |

## 4. 入口函数

### 4.1 evaluateRuntimeOutcome

```typescript
export async function evaluateRuntimeOutcome(input: EvaluateRuntimeOutcomeInput): Promise<RuntimeOutcomeResolution> {
  const fallbackEvaluation = buildRuleBasedChapterOutcome(input);

  // 门控逻辑
  const isNaturalLanguage = isNaturalLanguageCompletionCondition(input.chapter);
  const isRuleContinue = fallbackEvaluation.hasRule && fallbackEvaluation.result === "continue";
  const shouldSkipAi = input.skipAi || (isRuleContinue && !isNaturalLanguage);

  const evaluation = (!shouldSkipAi)
    ? (await evaluateChapterOutcomeByAi(input) || fallbackEvaluation)
    : fallbackEvaluation;

  // 结果收口
  const outcome = evaluation.hasRule ? evaluation.result : (input.fallbackOutcome || "continue");
  const nextChapterId = evaluation.hasRule ? evaluation.nextChapterId : null;
  const sessionStatus = resolveSessionStatusByOutcome(String(input.fallbackStatus || "active"), outcome);

  return { evaluation, outcome, sessionStatus, nextChapterId };
}
```

### 4.2 入参说明

```typescript
interface EvaluateRuntimeOutcomeInput {
  userId?: number;              // 用户 ID
  world?: any;                  // 故事世界数据
  chapter: any;                 // 章节数据（包含 completionCondition、runtimeOutline）
  state: JsonRecord;            // 当前运行时状态（包含 chapterProgress）
  messageContent?: string;      // 用户最新发言内容
  eventType?: string;           // 事件类型（on_message / on_opening 等）
  meta?: JsonRecord;            // 额外元数据
  recentMessages?: any[];       // 最近 10 条对话记录
  fallbackStatus?: string;      // 兜底 session 状态
  fallbackChapterId?: number | null;   // 兜底下一章 ID
  fallbackOutcome?: "continue" | "guide" | "success" | "failed";  // 兜底结局
  applyToState?: boolean;       // 是否将结果应用到状态
  traceMeta?: JsonRecord;       // 追踪元数据（用于日志）
  skipAi?: boolean;             // 强制跳过 AI 判定
}
```

## 5. 规则引擎

### 5.1 evaluateChapterOutcome（ChapterOutcomeEngine）

规则引擎位于 `src/modules/game-runtime/engines/ChapterOutcomeEngine.ts`，提供快速的初步判定。

**判定顺序**：

1. 检查 `runtimeOutline.endingRules.failure` — 是否有已完成的事件触发失败条件
2. 检查 `runtimeOutline.endingRules.success` — 所有成功事件是否都已完成
3. 解析 `completionCondition`（结构化格式）并评估
4. 以上都不满足时返回 `continue`

**返回结构**：

```typescript
interface ChapterOutcomeResult {
  hasRule: boolean;                           // 是否存在有效规则
  result: "continue" | "guide" | "success" | "failed";
  nextChapterId: number | null;               // 下一章 ID
  matchedBy: "runtime_outline" | "completion_condition" | "none";  // 匹配来源
  matchedRule: string | null;                 // 匹配的规则标识
  reason?: string | null;                     // 判定原因
  guideSummary?: string | null;               // 引导摘要（guide 时）
  guideFacts?: string[] | null;               // 引导事实列表（guide 时）
}
```

### 5.2 自然语言检测 isNaturalLanguageCompletionCondition

```typescript
function isNaturalLanguageCompletionCondition(chapter: any): boolean {
  const condition = chapter?.completionCondition;
  if (typeof condition !== "string") return false;
  const text = condition.trim();
  if (!text) return false;
  try {
    const parsed = JSON.parse(text);
    if (typeof parsed === "object" && parsed !== null) {
      const ruleKeys = ["type", "op", "field", "conditions", "success", "failure", "pass", "fail"];
      if (ruleKeys.some((k) => k in parsed)) {
        return false;  // 是有效规则结构，不算自然语言
      }
    }
    return true;  // JSON 解析成功但无规则字段 → 自然语言
  } catch {
    return true;  // 不是有效 JSON → 自然语言
  }
}
```

## 6. AI 判定

### 6.1 evaluateChapterOutcomeByAi

当规则引擎无法处理（自然语言条件）或已命中条件时，调用 AI 进行判定。

**流程**：

1. 加载 `story-chapter` Prompt（从 `t_prompts` 表，code = `story-chapter`）
2. 构建 AI 输入快照（buildChapterJudgeInputSnapshot）
3. 调用 AI 模型（优先 `storyChapterJudgeModel`，兜底 `storyOrchestratorModel`）
4. 解析 AI 返回结果（支持 JSON object 或纯文本格式）
5. 返回 `ChapterOutcomeResult`

### 6.2 AI 输入结构（buildChapterJudgeInputSnapshot）

### 6.3 AI Prompt（story-chapter）

```markdown
你是章节判定器。你只判断当前章节是否成功、失败或继续，以及是否进入下一章。

## 任务
根据用户提供的章节信息、当前事件状态和运行态数据，判断章节是否应该结束。

## 特别注意
- 用户指的是台词里用户：recent_dialogue 数据里的 "role": "用户"
- 用户输入："2", 不是代表输入了两次！！！

## 入参说明
- current_event：当前事件
- next_event：该章节的下一事件，用于判断是否需要引导。一般来说没有下一事件，才需要 result="guide"

## 输出格式
必须只输出一个 JSON 对象，不要解释，不要代码块，不要 markdown 格式。

字段固定为：
- result: "continue" | "guide" | "success" | "failed"
- matched_rule: string | null - 命中的规则标识
- reason: string - 判定原因说明
- next_chapter_id: number | null - 下一章 ID
- guide_summary: string - 当 result="guide" 时的引导摘要
- guide_facts: string[] - 当 result="guide" 时的引导事实列表（1-3条）

## 输出规则
- result="continue" 时，无须给出 guide_summary 和 guide_facts
- result="guide" 时，必须给出 guide_summary 和 1~3 条 guide_facts
- result="success" 或 "failed" 时，guide_summary 置空串，guide_facts 置空数组
```

### 6.4 AI 输出 schema

```typescript
const chapterJudgeOutputSchema = {
```

## 7. 结果应用

### 7.1 applyChapterOutcomeToState

当 `outcome` 为 `success` 或 `failed` 时，调用此函数将结果应用到状态：

```typescript
export function applyChapterOutcomeToState(chapter: any, state: JsonRecord, outcome: ChapterOutcomeResult): void {
  // continue/guide: 不改变章节状态
  if (outcome.result === "continue" || outcome.result === "guide") return;

  // 标记章节完成/失败
  if (outcome.result === "success") {
    setValueByPath(state, "flags.chapterCompleted", true);
    setValueByPath(state, "flags.chapterFailed", false);
  } else if (outcome.result === "failed") {
    setValueByPath(state, "flags.chapterFailed", true);
  }

  // 插入 ending 动态事件
  upsertRuntimeDynamicEventState(state, {
    eventIndex: endingEventIndex,
    kind: "ending",
    summary: outcome.result === "success" ? "结束条件已达成" : "结束条件失败",
    status: "completed",
  });

  // 同步章节进度
  setChapterProgressState(state, {
    eventIndex: endingEventIndex,
    eventKind: "ending",
    eventStatus: "completed",
    completedEvents,
    fixedOutcomeLocked: true,
    pendingGoal: "",
    userNodeStatus: outcome.result === "success" ? "completed" : progress.userNodeStatus,
  });
}
```

### 7.2 状态字段

章节判定会影响以下状态字段：

| 字段 | 说明 |
|------|------|
| `flags.chapterCompleted` | 章节是否成功完成 |
| `flags.chapterFailed` | 章节是否失败 |
| `chapterProgress.pendingGoal` | 当前目标提示（成功/失败后置空） |
| `chapterProgress.eventStatus` | 事件状态变为 `completed` |
| `chapterProgress.fixedOutcomeLocked` | 锁定结局，防止重复判定 |
| `dynamicEvents` | 插入 `ending` 类型动态事件 |

## 10. 配置项

章节判定 AI 模型通过 `t_prompts` 表配置：

| code | 说明 |
|------|------|
| `story-chapter` | 章节判定 Prompt（System Prompt） |

| `storyOrchestratorModel` | 编排模型（章节判定的兜底） |

## 11. 设计原则

1. **快速路径优先**：规则引擎能处理的走规则引擎，避免不必要的 AI 调用
2. **自然语言必须走 AI**：无法被规则引擎解析的自然语言条件（如 `"用户成功抢夺顾子航的房间"`）必须由 AI 判定
3. **并发执行**：正式链中章节判定与候选编排并发执行，提升响应速度
4. **幂等判定**：通过 `fixedOutcomeLocked` 防止重复判定
5. **结果锁定**：一旦章节结局确定（success/failed），状态被锁定，AI 编排不再影响结局
