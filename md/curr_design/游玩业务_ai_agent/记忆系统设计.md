# 已有记忆模块
- ai agent "记忆管理器"维护的动态数据。它更像是长期的动态的摘要和存档记忆。
特点是动态和必要的动态数据。最终会存到每个台词的快照字段里，用于台词“回溯”功能等。
- 各个 agent 入参的最新台词list.和其他入参。
- 数据库数据。可以认为是深度记忆。但是不会发给大模型的数据。对于大模型来说是不可见的“记忆”

# 局限
由于"记忆管理器"是摘要为主的摘要和角色卡等的动态数据。那么必然有缺少部分信息的问题。

# 角色发言器-记忆检索补充
角色发言时，会进行记忆检索，将检索到的记忆信息，补充到“角色发言器”调用大模型的输入中作为参考。
对应的入参字段为“记忆片段”
### 如何获得“记忆检索片段”
- 首先根据什么检索？
剧情编排后->发言角色和发言动机
这个就是检索的入参。

- 用什么检索？
  - 比较低效的检索方式是"深度记忆检索器-检索阶段"这个大模型agent 去查数据库
  - 稍微高效但是麻烦的是"深度记忆检索器-检索阶段"这个大模型agent 去查向量库。那么就得把数据不断存入向量库了

- 检索后的加工
发给在线大模型为了省token 所以不能直接发送检索到的内容
需要独立的ai agent "深度记忆检索器-凝练阶段"来加工。
"深度记忆检索器" 根据发言角色和发言动机进行检索，然后凝练成适合补充到“角色发言器”的“记忆片段”。

# 记忆系统设计

## 1. 定位

记忆系统是整个 AI 故事系统的**信息中枢**，负责：

1. 维护故事的动态状态（谁做了什么、关系怎么变、任务到哪了）
2. 在正确时机把正确信息注入正确的 Agent
3. 在角色发言时提供「记忆片段」作为上下文补充

它不存储原始对话，而是存储**经过提炼的事实、关系和状态变化**。

## 3. 三级记忆体系

### 3.1 短期记忆（Short-term）

**内容**：最近几轮对话的事实摘要

**存储位置**：会话内存（进程内）

**用途**：注入编排师、角色发言器的实时上下文

**特点**：
- 每轮更新
- 按轮次追加，覆盖超过窗口的旧内容
- 是「记忆片段」的直接来源

### 3.2 中期记忆（Mid-term）

**内容**：重要事件、关系变化、任务进展、道具变化

**存储位置**：数据库（会话级）

**用途**：
- 记忆管理器在关键触发点写入
- 被深度记忆检索器查询
- 最终存入台词快照字段，支持回溯

**更新时机**（只在这几种情况下写入）：
1. 新关系建立或破裂
2. 用户做出明确立场选择
3. 新任务出现 / 任务完成 / 任务放弃
4. 关键道具出现或消失
5. 章节阶段切换
6. 章节成功或失败
7. 关键角色状态剧变
8. 重要剧情节点通过

### 3.3 长期记忆（Long-term）

**内容**：故事背景、世界观、角色卡、章节配置

**存储位置**：数据库（固定数据）

**用途**：一次性加载到编排上下文，提供稳定的世界信息

**特点**：
- 固定不变
- 由记忆管理器在会话初始化时注入
- 不参与实时更新循环

## 4. 记忆管理器

### 4.1 职责

记忆管理器是记忆系统的**写入侧**，负责：

1. 监听编排流程中的关键事件
2. 判断是否触发记忆更新
3. 生成记忆摘要（recentFacts、keyRelationships、importantItems、pendingTasks、criticalFlags）
4. 将关键变化写入中期记忆（数据库）
5. 维护「当前发言上下文」（由发言聚焦系统使用）

### 4.2 输出数据结构

```typescript
interface MemorySummary {
  recentFacts: string[];        // 最近事实（2~5条）
  keyRelationships: string[];   // 关键关系变化
  importantItems: string[];     // 重要道具状态
  pendingTasks: string[];       // 待办任务
  criticalFlags: string[];      // 关键标记（如已揭示真相、已背叛等）
}
```

### 4.3 异步原则

记忆更新**不阻塞首屏返回**：

```
发言成功后
    ↓
先提交消息
    ↓
后台排队做记忆更新
    ↓
成功后静默更新 memorySummary
```

## 5. 深度记忆检索器

### 5.1 职责

深度记忆检索器是记忆系统的**读取侧**，专门为「角色发言器」提供「记忆片段」。

它的输入是：发言角色 + 发言动机  
它的输出是：经过提炼的、适合塞进角色发言器上下文的「记忆片段」

### 5.2 两阶段设计

```
用户输入 → 编排师决定发言角色和动机
              ↓
        深度记忆检索器-检索阶段
              ↓ 检索数据库/向量库，返回候选记忆
        深度记忆检索器-凝练阶段
              ↓ 提炼成精炼的记忆片段
        角色发言器收到「记忆片段」入参
              ↓
        生成台词
```

**为什么分两阶段？**

- 检索阶段可能返回大量候选内容
- 直接发给在线大模型会超 token 限额
- 凝练阶段把候选内容压缩成 1~3 句精炼摘要

### 5.3 检索方式

| 方式 | 速度 | 准确度 | 维护成本 |
|---|---|---|---|
| 大模型直接查数据库 | 慢 | 高 | 低 |
| 向量相似度检索 | 快 | 中 | 高（需持续写入向量） |

**建议**：第一版用大模型直接查数据库（慢但准），后期有性能压力再迁移到向量检索。

### 5.4 输出格式

```typescript
interface MemoryFragment {
  relevantFacts: string[];    // 与发言相关的近期事实
  relationContext: string[];  // 关系上下文（如"萧炎曾当众羞辱你"）
  taskContext: string[];      // 任务上下文（如"当前任务：向纳兰嫣然证明自己"）
  tone: "neutral" | "emotional" | "urgent";  // 建议的语气倾向
}
```

## 6. 与发言聚焦系统的关系

### 6.1 发言聚焦系统负责什么

发言聚焦系统维护「当前发言上下文」：

```json
{
  "当前发言上下文": {
    "主区域": "诡异学校-教室",
    "激活角色列表": ["林小茹", "李老师"],
    "远程可发言角色": [],
    "本次例外角色": []
  }
}
```

它只回答一个问题：**「当前这一轮，哪些角色允许发言？」**

### 6.2 记忆系统负责什么

记忆系统维护「当前叙事状态」：

```json
{
  "当前叙事状态": {
    "主区域": "诡异学校-教室",
    "当前事件": "与李老师对峙",
    "当前任务": "逃离诡异学校",
    "关键关系": ["林小茹已对玩家产生信任"],
    "关键道具": ["神秘纸条（未解读）"],
    "最近变化": ["李老师露出真面目"]
  }
}
```

它回答：**「现在发生了什么？角色的记忆里应该有什么？」**

### 6.3 两者如何协作

```
意图分析师识别用户输入
    ↓
编排师决定发言角色
    ↓
发言聚焦系统提供「谁可以说话」
    ↓
记忆系统提供「记忆片段」（通过深度记忆检索器）
    ↓
角色发言器结合两者生成台词
```

具体来说：

- **编排师**需要发言聚焦系统过滤后的激活角色列表
- **角色发言器**需要记忆系统提供的记忆片段
- **意图分析师**在识别到场景切换时，同时触发两者更新

## 7. 与其他 Agent 的关系

### 7.1 与「编排师」的关系

编排师在构建 prompt 时，需要注入记忆摘要：

```
当前记忆摘要：
- 最近事实：玩家刚拒绝了萧炎的挑战
- 关键关系：萧炎对玩家产生敌意
- 待办任务：三天后与萧炎在练武场对决
- 关键标记：萧家已知道玩家的潜力
```

编排师不直接读原始对话，而是读记忆管理器提炼后的摘要。

### 7.2 与「意图分析师」的关系

意图分析师是记忆更新的**触发器**：

- 识别到用户做出重要选择 → 触发记忆更新
- 识别到场景切换 → 触发发言聚焦系统更新
- 识别到任务相关意图 → 触发任务状态更新

### 7.3 与「角色发言器」的关系

角色发言器是深度记忆检索器的**消费者**：

- 每轮发言前，角色发言器都会收到「记忆片段」入参
- 记忆片段来自深度记忆检索器的凝练输出
- 角色发言器根据记忆片段调整台词的语气和内容

### 7.4 与「章节阶段推进」的关系

章节切换是记忆更新的**强触发点**：

- 阶段切换时，记忆管理器写入阶段摘要
- 章节结束时，记忆管理器写入章节总结
- 新章节开始时，记忆管理器初始化新的短期记忆

## 9. 台词快照机制

### 9.1 为什么需要快照

台词最终要落库，每个台词记录需要包含「当时的记忆状态」，用于：

- **回溯功能**：用户回看历史台词时，能看到「当时发生了什么」
- **记忆一致性**：跨会话读取时，能恢复当时的叙事状态
- **调试**：出问题时有完整的上下文快照

### 9.2 快照字段

```typescript
interface DialogueSnapshot {
  dialogueId: string;
  sessionId: string;
  chapterId: string;
  phaseId: string;

  // 快照时的记忆状态
  snapshotMemory: {
    recentFacts: string[];
    keyRelationships: string[];
    pendingTasks: string[];
    criticalFlags: string[];
  };

  // 快照时的发言上下文
  snapshotFocus: {
    mainArea: string;
    activeRoles: string[];
    remoteRoles: string[];
  };

  // 快照时的任务状态（如果有）
  snapshotTask: {
    taskId: string | null;
    taskName: string | null;
    taskProgress: number;
  } | null;
}
```

### 9.3 快照写入时机

```
角色发言器生成台词
    ↓
台词落库（异步）
    ↓
同时写入快照字段（记忆摘要 + 发言上下文 + 任务状态）
    ↓
回溯时可通过 dialogueId 查询快照，还原当时的完整状态
```

## 10. 总结

记忆系统的核心价值：**在每个剧情轮次，让所有 Agent 看到一致的故事状态。**

三个核心组件各司其职：

| 组件 | 职责 | 回答的问题 |
|---|---|---|
| 记忆管理器 | 写入侧，提炼事实 | 「发生了什么重要的事？」 |
| 深度记忆检索器 | 读取侧，补充上下文 | 「角色发言时该记住什么？」 |
| 发言聚焦系统 | 上下文广播 | 「现在谁可以说话？」 |

三者配合，让编排师、角色发言器、意图分析师在任何时刻都基于同一份「故事状态」工作。
