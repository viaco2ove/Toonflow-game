# 章节判定设计

## 1. 概述

章节判定（ChapterOutcomeEngine）负责评估章节是否结束，以及结局是成功还是失败。

## 2. 章节状态

| 状态 | 说明 |
|------|------|
| `continue` | 章节继续进行 |
| `success` | 章节成功结束 |
| `failed` | 章节失败结束（已完全不可能成功） |

## 3. 章节结构

### 3.1 ChapterRuntimeOutline

```typescript
interface ChapterRuntimeOutline {
  openingMessages: Array<{ role, roleType, content }>;  // 开场消息
  phases: ChapterRuntimePhase[];                        // 阶段列表
  userNodes: ChapterRuntimeUserNode[];                  // 用户节点
  fixedEvents: Array<{                                  // 固定事件
    id: string;
    label: string;
    requiredBeforeFinish: boolean;
    conditionExpr: string;
  }>;
  endingRules: {                                       // 结局规则
    success: string;
    failure: string;
    nextChapterId?: string;
  };
}
```

### 3.2 Phase 图结构

```typescript
interface ChapterRuntimePhase {
  id: string;
  label: string;
  kind: "opening" | "scene" | "user" | "fixed" | "ending";
  allowedSpeakers: string[];      // 允许发言的角色
  nextPhaseIds: string[];         // 下一阶段
  completionEventIds: string[];   // 完成信号
}
```

## 4. 判定流程

### 4.1 正常章节判定

```
编排发送：
  - 对话内容（砍为10个台词）
  - 当前事件内容
  - 事件序号
  - 各个角色简洁的文字化动态参数卡

编排大模型返回：
  - 下个角色
  - 角色动机
  - 事件内容是否需要调整
  - 是否需要触发记忆管理

判断是否达到结束条件：
  - 没有达到 → 继续编排
  - 事件内容为空 → 返回新的事件内容，创建新的动态事件数据

章节状态变化：
  - 未结束
  - 成功
  - 失败（已经完全不可能成功的意思）
```

### 4.2 自由章节判定

**特点**：
- 零个或有限的静态事件数据
- 没有结束条件
- 当前章节事件可能为空

**流程**：
- 用完有限的静态事件数据转成的动态事件数据后
- AI 不断产生新的事件加入到动态事件
- 永远不结束，除非用户主动退出或切换章节

## 6. 完成条件检测

### 6.1 固定事件完成

当 `fixedEvent` 的 `conditionExpr` 满足时，标记为完成。

### 6.2 用户节点完成

当用户输入满足 `userNode` 的触发条件时，标记为完成。

### 6.3 AI 判断兜底

当规则无法判断时，调用 AI 编排师判断章节是否应该结束。

## 7. 与其他模块的关系

- **ChapterProgressEngine**：提供 phase 图遍历
- **TriggerEngine**：执行触发器动作，可能影响章节进度
- **TaskProgressEngine**：任务完成可能触发章节结束
- **NarrativeOrchestrator**：编排结果包含章节结局建议
