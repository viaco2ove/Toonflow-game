# 事件管理设计

## 1. 概述

事件管理是 AI 故事系统的核心机制，通过事件驱动叙事，控制章节内的 phase 推进和事件完成。

## 2. 事件类型

| 类型 | 说明 |
|------|------|
| `opening` | 开场事件 |
| `scene` | 场景事件 |
| `user` | 用户节点事件 |
| `fixed` | 固定事件 |
| `ending` | 结尾事件 |

## 3. 事件进度状态标记

每个事件阶段都有进度状态标记，用于显示当前进度：

| 标记 | 状态 | 说明 |
|------|------|------|
| `[]` | 空闲/未开始 | 阶段尚未开始 |
| `[i]` | 进行中 | 阶段正在执行 |
| `[s]` | 完成 | 阶段已完成 |
| `[f]` | 失败 | 阶段失败 |

**示例**：
```
事件 1：[s]石板硌着后背 → []天际裂缝 → []远处打斗声 → []用户发言
事件 2：[s]黑术暗影君王的窥探 → [s]旁白引导剧情 → [i]遇见与交流
```

**数据结构**：
```typescript
interface StageProgress {
  index: number;        // 阶段索引
  label: string;        // 阶段标签
  status: "" | "i" | "s" | "f";  // 进度状态
  kind: string;         // 阶段类型
  summary: string;      // 阶段摘要
}

interface EventProgress {
  eventIndex: number;
  phaseId: string;
  summary: string;      // 带状态标记的摘要，如 "[s]阶段1 → [i]阶段2 → []阶段3"
  status: "idle" | "active" | "waiting_input" | "completed";
  stageProgress: StageProgress[];  // 各阶段进度详情
  currStageIndex: number;          // 当前阶段索引
  currStageSummary: string;        // 当前阶段摘要
}
```

## 4. 动态事件 vs 固定事件

### 4.1 固定事件

有明确的结束条件和触发条件，预先定义在章节中。

```typescript
interface FixedEvent {
  id: string;
  label: string;
  requiredBeforeFinish: boolean;
  conditionExpr: string;
}
```

### 4.2 动态事件

由 AI 编排师动态生成，没有预定义结束条件。

**特点**：
- 零个或有限的静态事件数据
- 没有结束条件
- 当前章节事件可能为空时，AI 不断产生新事件

## 5. 事件状态

```typescript
interface RuntimeDynamicEventState {
  eventId: string;
  phaseId: string;
  flowType: "fixed" | "dynamic";
  runtimeFacts: Record<string, any>;
  memorySummary: string;
  status: "idle" | "active" | "waiting_input" | "completed";
}
```

| 状态 | 说明 |
|------|------|
| `idle` | 空闲，等待触发 |
| `active` | 活跃，正在执行 |
| `waiting_input` | 等待用户输入 |
| `completed` | 已完成 |

## 6. 事件流转

```
Opening → Phase 1 (scene) → Phase 2 (user) → ... → Ending → Next Chapter
              ↓                   ↓
         completionEvent      userNode 完成触发
```

## 7. ChapterProgressEngine

### 7.1 核心职责

- Phase 图遍历
- 事件完成追踪
- 自由章节动态事件处理
- AI 事件进度检测
- 事件完整性验证

### 7.2 关键方法

- `resolveCurrentOrInitialPhase()`：解析当前 phase
- `arePhaseCompletionEventsMatched()`：判断 phase 是否完成
- `advanceChapterProgressAfterNarrative()`：推进章节进度
- `recordChapterProgressSignals()`：记录推进信号
- `resolveNextPhaseFromGraph()`：根据 phase 图解析下一 phase
- `ensureFreeChapterDynamicEventState()`：自由章节动态事件状态初始化
- `applyAiEventProgressResolution()`：AI 进度检测推进章节

## 8. 事件完成检测

### 8.1 条件完成

当 `evaluateCondition(condition, context)` 返回 true 时，事件完成。

### 8.2 AI 补底

当规则无法判断时，调用 AI 判断事件是否完成。

## 9. 台词事件标记

每条台词都需要标记其所属的事件和阶段，以便事件进度检测器判断台词归属：

```typescript
interface DialogueMessage {
  role: string;
  roleType: string;
  eventType: string;
  content: string;
  // 事件/阶段标记
  eventIndex: number | null;      // 所属事件索引
  stageIndex: number | null;      // 所属阶段索引
  // 角色发言计数
  roleNumSpeechCurrEvent: number; // 该角色在当前事件的发言次数
  roleNumSpeechCurrStage: number; // 该角色在当前阶段的发言次数
}
```

**示例**：
```json
{
  "role": "薰儿（萧薰儿|古薰儿）",
  "roleType": "npc",
  "content": "敢问阁下是迷途落在此处的旅人吗？",
  "eventIndex": 2,
  "stageIndex": 2,
  "roleNumSpeechCurrEvent": 1,
  "roleNumSpeechCurrStage": 1
}
```

## 10. 事件日志

每个事件完成后，记录到 `completedEvents` 列表：

```typescript
completedEvents: [
  "phase:phase_1",
  "user_node:user_node_1",
  "fixed_event:success",
  "event:event_1",
  "event:event_2"
];
```

## 11. 与其他模块的关系

- **ChapterOutcomeEngine**：评估章节结局
- **TriggerEngine**：触发器可能影响事件状态
- **NarrativeOrchestrator**：编排结果决定下一事件
- **SessionService**：事件状态存储在会话快照中
- **EventProgressRuntimeService**：AI 事件进度检测服务

# 谁把 [i] 改成[s]
ChapterProgressEngine.ts:1549 — 把 stageIndex 从 0 改成 1
gameEngine.ts:1949 — /game/storyInfo 读取时，发现 j(0) < stageIndex(1)，就算出 [s]

**`ChapterProgressEngine.ts:1549`** —— 编排师跑完一轮后，`syncChapterProgressWithRuntime` 调用 stage 推进逻辑，执行 `setChapterProgressState(state, { stageIndex: nextStageIndex })`。

不完全是。有个前提条件：当前 stage 的 kind 必须是 scene。

当前 stage 是 scene（如"苏醒"）-> 编排师跑完输出旁白 -> stageIndex+1 -> 旧的变 [s]
当前 stage 是 user（如"用户发言"）-> 编排师不跑，等用户输入 -> stageIndex 不动
所以准确说法是：编排师跑完一个 scene stage 后，stageIndex +1，那个 scene stage 就从 [i] 变 [s]。

# 谁会把[i] 卡住？
日志找到了根因：[i] 没变 [s] 是因为编排师的 event_adjust_mode 是 keep，stage 没有推进。

具体链路：

用户发 .（行340）→ 编排师第一轮跑完，输出旁白
章节判定器返回 result="guide"（行82）→ "苏醒场景尚未完成，需要引导用户"
discard_candidate 丢弃第一轮结果（行380）→ 第一轮编排被废弃

编排师返回 event_adjust_mode: "keep"（行399）→ 事件状态保持 active，stage 不推进
