# 编排请求——流程设计

## 1. 概述

`/game/orchestration` 是游玩核心接口，负责决定本轮由谁发言及剧情推进一小步。

## 2. 核心流程

```
请求入口 (/game/orchestration)
    │
    ▼
┌─ 清理并发冲突 ─────────────────────────────────────────────┐
│ 检查是否有正在进行的编排请求，冲突则等待或丢弃旧请求                    │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 会话锁定 ─────────────────────────────────────────────────┐
│ runtimeProcessingPending = true，防止并发撞车                               │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 并发执行（两条线同时跑）────────────────────────────────────────┐
│                                                              │
│  线程A: runNarrativePlan()      线程B: evaluateRuntimeOutcome()  │
│  编排师生成 role/motive/await_user │ 章节/事件判定 outcome/nextChapterId │
│                                                              │
└──────────────────────────────────────────────────────────┘
    │                    │
    ▼                    ▼
   candidatePlan      mergedOutcome
    │                    │
    │                    ├─ continue ──────────────────────────► 采用编排结果
    │                    ├─ guide ───────────────────────────► 丢弃编排，重新跑编排 + guide 提示词
    │                    ├─ success ───────────────────────► 章节切换完成
    │                    └─ failed ────────────────────────► 章节失败
    ▼
concurrent_arbiter（并发仲裁）
    │
    ├─ continue（正常）：采纳编排结果
    │
    ├─ guide（引导用户完成章节条件）：
    │   ① 丢弃 candidatePlan
    │   ② 用 mergedOutcome.evaluation.reason 拼 guide 提示词
    │   ③ 以 guideHint 作为 playerMessage 重新跑 runNarrativePlan
    │   ④ 采用重新编排的结果
    │
    ├─ success/failed：章节切换 / 失败
    │
    └─ 其他非 continue outcome：丢弃编排，plan = null
```

## 3. guide 分支详解（重点）

**场景**：章节完成条件未满足，但编排师已编排了旁白/NPC 说话。

**之前的问题**：`outcome=guide` 时直接硬编码返回 `{role:"用户"}`，覆盖了编排结果，用户看到的是"等待输入"而非旁白/NPC 发言。

**修复后**：
1. `discardCandidatePlan()` — 丢弃当前编排结果
2. 取 `mergedOutcome.evaluation.reason`（如"用户连续输入.，未推动剧情"）
3. 拼成 `playerMessage = "[引导提示] 用户连续输入.，未推动剧情，当前章节需要收到陌生短信"`
4. 重新跑 `runNarrativePlan(playerMessage = guideHint)`，让编排师选合适的角色引导用户
5. 返回编排师的重新编排结果

```
章节判定 outcome=guide
    │
    ▼
guide_reason = "用户连续输入.，未推动剧情，当前章节需要收到陌生短信"
    │
    ▼
playerMessage = "[引导提示] 用户连续输入.，未推动剧情，当前章节需要收到陌生短信"
    │
    ▼
重新跑 runNarrativePlan(playerMessage = guideHint)
    │
    ▼
编排师生成：旁白/NPC 发言（引导用户收到短信的剧情）
    │
    ▼
返回实际的角色台词和 motive
```

## 4. 关键日志节点

| 日志节点 | 说明 |
|---|---|
| `concurrent_arbiter:start` | 并发仲裁开始，两条线同时执行 |
| `concurrent_arbiter:judge_done` | 章节判定完成，outcome=guide/continue/success/failed |
| `concurrent_arbiter:discard_candidate` | 丢弃编排候选（reason=guide 时重跑编排 |
| `concurrent_arbiter:rerun_with_guide` | guide 场景重新跑编排 |
| `buildMinimalOrchestrationResponse` | 最终返回给前端的 role/roleType/motive |
