# 速度优化

## 1. 概述

通过优化对话链路、减少上下文、精简接口，实现更快速的用户体验。

## 2. 核心优化策略

### 2.1 Agent 功能单一化

- 编排师只负责决定角色和动机，不写台词
- 角色发言独立接口，不占用编排时间
- 记忆管理后台异步执行，不阻塞主流程

### 2.2 数据发送优化

#### 2.2.1 记忆管理数据

**记忆管理会产生什么数据**：
- 故事动态背景精炼总结
- 用户参数 JSON 转精炼文本
- 章节内容精炼文本
- 角色信息精炼文本
- 故事动态参数
- 角色动态参数

#### 2.2.2 数据来源

- 最近对话（最多记录 20 条）
- agent 已处理的缓存信息
- 用户参数 JSON 转精炼文本
- 章节内容精炼文本
- 角色信息精炼文本
- 故事动态参数
- 角色动态参数

### 2.3 数据初始化

持久化绑定到当前对话：
1. 加载故事动态背景精炼总结（加载，缺少才生成）
2. 加载角色动态参数卡（加载，缺少才生成）
3. 加载故事动态参数（加载，缺少才生成）
4. 加载角色精炼文字（加载，缺少才生成）

**注意**：故事发布时（调试时也）先预先生成一份静态的，用于第一次进入快速生成动态数据。

## 3. 优化后的流程

### 3.1 编排师优化

**输入精简**：
```
获取最近的对话（最多记录 10）+故事背景（背景总结）+用户参数（精炼文本）
+当前章节内容（精炼文本）+角色信息（精炼文本）+agent 提示词
→ 发送大模型
→ 返回：角色 + 动机（简洁，20字以内）
```

**关键优化**：
- 基础模式下禁止 think
- 直接返回内容到角色台词框

### 3.2 角色发言优化

**输入精简**：
```
获取最近的对话（最多记录）+故事背景（背景总结）+自身参数（精炼文本）
+用户参数（精炼文本）+当前章节内容（精炼文本）+角色信息（精炼文本）
→ 发送大模型
→ 流式返回：角色台词
```

**关键优化**：
- 基础模式下禁止 think
- 尽量减少上下文

### 3.3 记忆管理优化

- 完全独立的线程
- 后台异步进行记忆整理
- 监听对话是否有新变动
- 角色参数变化、背景信息变化自动处理
- 大约 30 秒扫一次

### 3.4 用户发送优化

**当前问题**：用户发送等半天

**优化后**：
```
用户发送
→ 后端增加用户台词到对话（持久化）
→ 直接返回成功到前端
→ 触发异步记忆管理（判断是否需要扫描和更新）
→ 前端发送下一次编排请求
```

## 4. 接口设计

### 4.1 编排接口 `/orchestration`

**只返回**：
- speaker
- motive

**不返回**：完整剧情正文

### 4.2 流式台词接口 `/streamlines`

**流式返回**：单纯的台词文字

### 4.3 流式语音接口 `/streamvoice`

**触发条件**：台词遇到 `。！？` → 强切

### 4.4 接口结束标记

```
/streamlines ended
    ↓
/orchestration ended
    ↓
下一轮循环...
```

## 5. 轮空问题处理

### 5.1 问题描述

会不会因为播放完毕 + 已编排下一位角色的判断不准确，导致没有下个角色发言？

### 5.2 解决方案

使用 LocalStorage 记录数据：

```json
{
  "toonflow.chat": [{
    "对话id": "",
    "当前台词序号": 0,
    "当前台词角色": "",
    "当前台词文本": "",
    "当前台词状态": "pending|playing|ended",
    "下一个编排角色": ""
  }]
}
```

### 5.3 状态同步

1. **播放完语音状态改变**：播放完语音状态应该改变
2. **重试机制**：播放语音遇到问题应该有重试机制

## 6. 角色台词格式优化

### 6.1 当前问题

```
萧炎
黑色身影裹着淡紫异火流光落于混沌晶石另一侧，
玄色战袍上的红纹随翻腾斗气隐隐发亮，萧炎剑眉一挑
，声冷如锋：
这神棒能量引我至此，今日，我萧炎也要争这定海神针。
```

### 6.2 优化后

```
萧炎
(黑色身影裹着淡紫异火流光落于混沌晶石另一侧，
玄色战袍上的红纹随翻腾斗气隐隐发亮，萧炎剑眉一挑
，声冷如锋)
这神棒能量引我至此，今日，我萧炎也要争这定海神针。
```

**要求**：
- 非台词用小括号包起来
- 小括号内容不转语音

## 7. 编排师进一步优化

### 7.1 时机优化

- 角色文字一出完就下一次编排，不需要等待语音播放
- 返回前端后判断上一个是否已经说完话，说完话就让下一个角色说话
- **目标**：减少编排师的延时感

### 7.2 工作难度优化

- 进一步优化编排师的工作难度
- 减少发送给大模型的文字量
- 记忆管理师总结要更凝练简洁明了
- **目标**：编排师 15 秒左右出结果

## 8. 豆包模型速度优化

### 8.1 关闭思考模式

```json
{
  "model": "doubao-seed-2-0-lite-260215",
  "reasoning_effort": "minimal",
  "max_output_tokens": 131072
}
```

### 8.2 实际测试结果

官方体验网页耗时约 3 秒。

### 8.3 关键参数

- `reasoning_effort`: `"minimal"` - 关闭思考模式
- 不要使用 `thinking.type: disabled`（这是错误的参数名）

## 9. 禁用接口

**不想再看见**：`debugStep` 这个大杂烩接口

**应该的设计**：
- `/orchestration`：只返回角色 ID 和动机
- `/streamlines`：单纯的文字流
- `/streamvoice`：流式语音
