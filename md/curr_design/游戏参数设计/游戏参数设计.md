# 游戏参数设计

## 1. 概述

游戏参数设计用于补齐"角色参数卡"之外的游戏运行时参数，目标是：

1. 存储每个用户独立的游玩进度与动态状态
2. 把关键信息结构化，避免只依赖聊天全文导致遗忘
3. 为 LLM 提供可控上下文装载（短/中/长期记忆）

本设计聚焦 `game_run` 维度，不改动角色卡基础模型。

## 2. 运行时核心对象

一个用户进入一个故事后，生成一个运行实例 `game_run`。该实例包含以下核心参数域：

| 参数域 | 说明 |
|--------|------|
| `progress` | 章节进度、场景进度、主支线任务进度 |
| `world_state` | 世界动态变化（势力关系、场景状态、全局变量） |
| `player_state` | 用户当前所处地点、身份状态、关键资源 |
| `event_pool` | 已触发/待触发事件，含条件和结果 |
| `relationship_state` | 用户与主要角色关系值与关系标签变化 |
| `memory_state` | 短期、中期、长期记忆索引与摘要 |

## 4. 三级记忆系统

### 4.1 短期记忆（Short-Term）

**用途**：保证当前对话连续性

| 项目 | 说明 |
|------|------|
| 容量 | 最近 `8~16` 轮消息 |
| 内容 | 最近一次用户输入、最近一次系统决策、最近一次事件结果 |
| 生命周期 | 短，超过窗口自动出队 |

### 4.2 中期记忆（Mid-Term）

**用途**：保留关键剧情事实，避免"上下文爆炸"

| 项目 | 说明 |
|------|------|
| 格式 | "事实条目"，不存全文 |
| 每条事实 | `topic`、`content`、`importance`、`source_turn`、`ttl` |
| 更新频率 | 建议每 `4~8` 轮执行一次 |

### 4.3 长期记忆（Long-Term）

**用途**：保证世界观与角色关系稳定

| 项目 | 说明 |
|------|------|
| 内容 | 全局设定与已确认长期变化（阵营变化、永久伤害、世界事件） |
| 策略 | 不高频更新，采用"确认后写入"策略 |
| 版本绑定 | 与 `story_bible` 版本绑定，支持回溯与重放 |

## 5. 记忆管理 Agent 设计

### 5.1 输入输出

- **输入**：最近消息窗口 + 当前 snapshot + 上一版中期摘要
- **输出**：`memory_delta`（新增/更新/删除）+ `new_mid_summary`

### 5.2 执行流程

```
1. 抽取事实：识别事件、关系变化、任务变化、地点变化
2. 打分去重：按 importance + recency 去重聚合
3. 分类入池：短期保留在窗口，中期写事实库，长期只写"确认事实"
4. 生成索引：按 topic、role_id、chapter_id 建索引
5. 产出注入包：给下一轮推理使用的最小上下文集合
```

## 6. 上下文装载策略

每轮请求模型时按顺序装载：

| 顺序 | 内容 | 预算占比 |
|------|------|---------|
| 1 | 系统指令：玩法规则 + 安全规则 | 预留 10% |
| 2 | 长期记忆：世界观、永久状态、关键角色关系 | 15% |
| 3 | 中期记忆：高重要事实摘要（限制条数，如 `10~20` 条） | 35% |
| 4 | 短期记忆：最近对话窗口 | 40% |
| 5 | 当前输入：用户本轮输入 | - |

## 7. 与角色参数卡的联动

### 7.1 关系

- `role.parameterCardJson` 作为初始角色配置源
- `relationship_state`、`inventory`、`ability_cd` 等变化写入 `game_run` 层
- 不回写原始角色卡

### 7.2 周目继承

如果需要"继承存档开新周目"，从 `game_run_snapshot` 派生新 run。

## 8. 更新流程

每轮处理建议顺序：

```
1. 写入消息日志
2. 执行事件判定与任务判定
3. 生成 state_delta
4. 应用 state_delta 到内存态
5. 必要时写 snapshot
6. 触发记忆管理 Agent（按轮次或事件阈值）
7. 生成下一轮模型上下文
```

## 9. MVP 实施计划

### 先做（必须）

1. `game_run + snapshot + event + memory(short/mid)` 四层落地
2. 中期记忆抽取与摘要（可先规则 + LLM 混合）
3. 章节进度、地点、任务、关系值四类核心参数

### 后做（增强）

1. 长期记忆自动确认机制
2. 记忆冲突检测与自动修复
3. 多模型协同（主剧情模型 + 记忆模型 + 事件模型）

## 10. 交付结论

游戏参数设计采用"**snapshot + delta + 分级记忆**"路线：

| 机制 | 作用 |
|------|------|
| `snapshot` | 负责可回放、可恢复 |
| `delta` | 负责轻量高频更新 |
| 分级记忆 | 负责降低上下文成本并提升连续性 |
