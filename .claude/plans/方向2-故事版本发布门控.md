# 方向2 落地实施计划：故事版本感知 + 发布门控（单版本覆盖）

> 设计文档：`md/curr_design/游戏参数设计/故事版本设计.md`（方向2）
> 目标：草稿/发布分离 + runtime 改读发布表 + 版本感知 + 确定性进度对齐。

## 0. 关键决策（已与用户确认）

1. **范围**：玩家侧 runtime 全切 published——含 SessionService(19处) + TaskProgressEngine + TriggerEngine + SessionMemoryWorker + 玩家入口路由(startSession/introduction 正式游玩分支/streamlines/storyInfo/getSession/listSession)。作者编辑/调试链路(saveChapter/getChapter/orchestration debug/debugStep/debugRuntimeShared/copyWorld/saveTask/saveTrigger)留草稿。
2. **版本号**：`t_storyWorld_published.version` 自增；session 记 `worldVersion`，比较 `session.worldVersion` vs `published.version`。
3. **迁移**：initDB 建表（新环境）+ fixDB `ensureTable`/`addColumn` 幂等（老环境）+ 存量回填。
4. **发现（设计文档遗漏）**：runtime 不仅读 chapter `content`，还读该章的 `t_chapterTrigger`（TriggerEngine.ts:184）、`t_chapterTask`（TaskProgressEngine.ts:89）。发布门控必须一并快照 trigger/task，否则作者改触发器仍静默影响在运行 session。**方案**：把该章的 trigger/task 行打包成 JSON 存进 `t_storyChapter_published` 的新列（`triggersJson` / `tasksJson`），不另建 published 表（单版本、量小）。

## 1. 数据层

### 1.1 新表（initDB.ts 建表 + fixDB.ts `ensureTable` 幂等，builder 两边一致）

```
t_storyWorld_published
  id            INTEGER PRIMARY KEY
  worldId       INTEGER          -- 原草稿世界ID
  version       INTEGER          -- 发布版本号，每次发布 +1
  publishedAt   INTEGER
  publishedBy   TEXT
  -- world 整行快照（与 t_storyWorld 同字段：name/intro/coverPath/settings/playerRole/narratorRole/projectId 等）
  name, intro, coverPath, settings, playerRole, narratorRole, projectId, createTime, updateTime
  UNIQUE(worldId)                -- 单版本：一个 worldId 一行，发布时覆盖
  INDEX(worldId)

t_storyChapter_published
  id              INTEGER PRIMARY KEY
  worldPublishId  INTEGER        -- 关联 t_storyWorld_published.id
  chapterId       INTEGER        -- 原草稿 chapterId（不变，映射用）
  title           TEXT
  content         TEXT           -- 正文快照（不压缩）
  runtimeOutline  TEXT           -- 解析后 outline 快照
  sort            INTEGER
  -- 章节级运行配置快照（设计文档遗漏项的补全）
  openingRole, openingText, bgmPath, bgmAutoPlay, backgroundPath,
  entryCondition, completionCondition, showCompletionCondition
  triggersJson    TEXT           -- 该章 t_chapterTrigger 行数组（JSON）
  tasksJson       TEXT           -- 该章 t_chapterTask 行数组（JSON）
  publishedAt     INTEGER
  UNIQUE(worldPublishId, chapterId)
  INDEX(worldPublishId)
  INDEX(chapterId)
```

> 字段名与草稿表完全一致 → `normalizeChapterOutput`、`buildChapterRuntimeOutline` 可直接复用，无需改归一化链路。

### 1.2 新列（fixDB.ts `addColumn` 幂等 + 回填）

- `t_gameSession` + `worldPublishId INTEGER`、`worldVersion INTEGER`
- （`t_storyWorld` 不新增 version 列——版本号只在 published 表）

### 1.3 `database.d.ts`

**不手改**。dev 启动时 `initKnexType` 自动重新生成。新表/新列出现后 consumer 才能类型安全查询。

## 2. 发布逻辑改造（`src/lib/worldPublish.ts`）

`publishWorldSynchronously` 在现有流程末尾（`updateWorldPublishState(published)` 之后）新增「复制快照到 published 表」：

1. 读当前 published 行 `version`（无则 0），新 `version = old + 1`。
2. 读该 world 全部 `t_chapterTrigger`、`t_chapterTask`（按 chapterId 分组）。
3. **覆盖写** `t_storyWorld_published`（UNIQUE(worldId) → upsert/先删后插），整行复制 world 字段（含 settings 里的 `chapterInitialSnapshots`），写 `version`/`publishedAt`/`publishedBy`。保留新自增 `id`。
4. 删旧 `t_storyChapter_published where worldPublishId=旧id`（若有），按新 published.id 批量插入每章快照（content/runtimeOutline/排序字段 + 该章 triggersJson/tasksJson）。
5. 保留现有 `t_storyWorld.publishStatus` 翻状态逻辑（草稿表仍记 published 状态供作者侧展示）。

> 抽一个 `snapshotWorldToPublished(db, { worldId, userId, enrichedWorld, chapters })` 辅助函数，事务内执行 3-4。

## 4. 确定性进度对齐（新模块 `src/modules/game-runtime/services/progressAlign.ts`）

按设计文档「动态数据处理」6 步：

1. 取旧 outline phase 列表（从 session state 记录或旧快照）与新 published outline。
2. `phaseId` 在新 outline 存在 → 直接用；否则同名 → 相近索引就近 → 回退首 phase、eventIndex 清零。
3. `completedEvents`/`recentEvents` 失效 phaseId：能映射映射，不能丢弃。
4. 其余动态数据（facts/flags/vars/npcs/memory）一字不改。
5. `turnState` 重置为「等待玩家输入」安全态。
6. 生成对齐报告 `{ mapped: [], fallback: [], dropped: [] }`，存入 session state 供前端弹框预览。

输入：旧 state + 新 published chapter outline。输出：对齐后 state + 报告。零 token、幂等、纯本地。

## 9. 风险与验证

- **runtime 遗漏某处没切** → 静默读草稿。验证：grep 确认玩家 runtime 链路无残留 `db("t_storyChapter")`（作者链路保留）；跑一遍完整 session（开场→切章→触发器→任务→记忆）对比行为。
- **回填把旧 session 标到错误版本** → 旧 session 立刻触发对齐。验证：回填后旧 session `worldVersion` = 该 world 当前 published.version（即"已对齐"），不误触发。
- **兼容旧 session（无 worldPublishId）** → loadSessionWorld/loadPublishedChapter 回退草稿，保证不崩。
- **database.d.ts 未生成** → 类型报错。验证：dev 启动一次确保 initKnexType 跑过再编译。
